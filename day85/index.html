02

先備能力與三個本課概念

開始前先確認
  • 能將 UI、Kernel、OS、資料庫、Receiver 五層目前與目標版本分開記錄。
  • 能核對支援矩陣的部署範圍、版本組合、文件日期與依賴順序。
  • 能區分觀察、假設、驗證與變更 Gate；缺少受控來源或超出核准範圍時停止。
現況組合

每一元件版本必須取自該元件自己的證據，不以 UI 版本推導其他層。

別混淆：版本號相近也可能屬不同發布節奏。

支援邊

相容矩陣要能指出哪份文件明確涵蓋來源與目標組合；未涵蓋就是 UNKNOWN。

別混淆：其他環境成功不能取代本環境正式支援證據。

升級順序

依賴決定先後與中間支援狀態，任何跳版都需要明示依據及回復點。

別混淆：只看最終版本相容不代表中間步驟安全。

05

跟著做：每一步都有預期與失敗訊號

1

抄錄五層目前與目標版本對

輸入：逐列使用元件、目前版本、目標版本。

預期：得到五個獨立版本對，不把 UI 版本當整機版本。

證據：矩陣保存五列模擬版本字串及來源。

失敗：漏元件、改寫版本或跨層推導即失敗。

2

評級五元件每列支援證據狀態

輸入：比較未提供、僅舊文件、未涵蓋、UNKNOWN。

預期：五列皆無足夠當期支援證據，Gate 全為 BLOCK。

證據：每列記文件日期、適用部署與缺口。

失敗：舊文件未核適用就判 PASS，或空白代替 UNKNOWN 即不通過。

3

建立依賴順序待確認圖

輸入：將 UI、Kernel、OS、資料庫、Receiver 的相依問題連到正式矩陣。

預期：圖只呈現需確認的先後與禁止組合，不生成升級路徑。

證據：每條邊有來源狀態及 owner。

失敗：無來源就自行排序或提供套件／路徑時停止。

4

執行五列 BLOCK 完整性審核

輸入：逐列核對版本、來源日期、依賴與 Gate。

預期：BLOCK=5、PASS=0，並列取得正式矩陣後的重新審查條件。

證據：統計表含五個元件名與阻塞原因。

失敗：任何一列無證據卻放行，或宣稱完整相容即退件。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

版本矩陣漏列元件、改寫模擬版本，或把 U-sim-7→U-sim-8 當作整機升級版本。

最小檢查：逐列核對 UI U-sim-7→8、Kernel K-sim-42→51、OS O-sim-A→B、資料庫 D-sim-3→4、Receiver R-sim-2→3 及各自來源。

預期：五個目前／目標版本對逐字保留、互不推導，每個元件都有自己的證據欄。

修正：恢復缺失或被改寫的版本對，將整機版本拆回五列；來源缺失者標示證據缺口，不以 UI 或相近版本號代填。

停止／升級：任一元件版本無獨立來源或與 fixture 不符時，不得聲稱已完成現況盤點或進一步推導相容性。

矩陣出現 PASS，原因只是沿用舊文件、欄位空白，或其他環境曾成功。

最小檢查：逐列檢查支援證據狀態：UI 未提供、Kernel 僅舊文件、OS 未涵蓋、資料庫與 Receiver 為 UNKNOWN；同時核對文件日期與適用部署。

預期：五列都因缺少當期且適用的正式支援證據而為 BLOCK，統計為 BLOCK=5、PASS=0。

修正：將沒有明確涵蓋目前／目標組合的 PASS 退回 BLOCK，空白改為 UNKNOWN，並為每列補上缺少的文件範圍、日期及查證 owner。

停止／升級：在取得涵蓋該部署與版本組合的當期受控矩陣前，任何一列都不得放行，也不得用 LAB 或他站經驗代替正式證據。

相依圖在沒有受控來源時自行排出升級先後，甚至列出套件、路徑或跳版方式。

最小檢查：檢查每條 UI、Kernel、OS、資料庫、Receiver 候選相依邊是否附來源狀態、owner、禁止組合與重新審查條件。

預期：圖只呈現待正式矩陣確認的相依問題與阻塞，不形成可執行的升級路徑。

修正：移除無來源的順序、套件與路徑，將每條邊改為待查問題，連到對應 BLOCK 原因及取得正式矩陣後的審查條件。

停止／升級：只要任一相依邊缺少受控來源或中間版本支援證據，就維持 BLOCK，不得提出或執行升級順序。
