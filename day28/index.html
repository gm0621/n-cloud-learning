02

先備能力與三個本課概念

開始前先確認
  • 能辨識 key=value 基本結構
  • 了解字串數字布林型別差異
  • 能設計正例反例與預期輸出
詞法分隔

Tag-Value 解析先定義 key、等號、值、引號、跳脫與紀錄分隔，而非只找等號。

別混淆：值內空白或等號可能是內容，不能一律再切割。

重複 key 政策

同一紀錄重複 key 時需明定保留首值、末值、陣列或拒絕，且留下原文。

別混淆：未寫入規格的臨時選擇會造成不可預測覆寫。

欄位型別契約

每個穩定欄位需定義名稱、型別、是否必填、空值與失敗 fallback。

別混淆：看起來像數字的字串不一定允許自動轉型。

位置、版本與安全 Gate

G0／G2

  1. G0 可用去識別樣本反覆練習。

05

跟著做：每一步都有預期與失敗訊號

1

盤點分隔符引號與跳脫規則

輸入：五筆去識別原文及空白、引號、重複案例

預期：可逐字指出 key 與完整 value 邊界

證據：詞法規則與每筆 token 清單

失敗：直接用空白切割引號內的複合值

2

建立至少五欄的型別字典

輸入：user、action、result、note、zone 候選欄位

預期：每欄具有型別、必填、空值與未知策略

證據：版本化欄位字典與擁有者欄位

失敗：只列欄位名稱而沒有型別與失敗處理

3

執行正例與三類反例測試

輸入：標準、引號、重複、缺值與未知 key

預期：五案例輸出完全符合 fixture 的預期

證據：逐欄 expected 與 actual 差異為零

失敗：重複 key 無聲覆寫或缺值丟棄整筆

4

保留原文並驗證可回查性

輸入：解析欄位、原始紀錄與測試案例 ID

預期：每個欄位都能追溯到原文位置

證據：五案例皆有原文索引與 parser 版本

失敗：解析後刪除原文導致無法核對

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

引號內空白被切成兩個 token

最小檢查：檢查 tokenizer 是否先處理引號與跳脫

預期：引號閉合前的空白都屬於同一 value

修正：改用狀態式詞法規則並全組回歸

停止／升級：引號未閉合時標記失敗而非猜測

重複 key 只剩最後一個值

最小檢查：核對重複策略與資料結構是否支援多值

預期：兩個值皆保留且產生明確警告

修正：改存陣列或依核准政策拒絕該筆

停止／升級：政策未定前不得選任一值作業務判讀

數字型欄位轉型失敗

最小檢查：檢查空白、符號、小數點與區域格式

預期：合法值轉型，非法值保留原文與錯誤狀態

修正：增加嚴格格式驗證與 typed fallback

停止／升級：不得把失敗值默認為零

教師版與錯項解析

案例答案

必須定義重複 user、引號內空白與未知 key 的處理，並保留原文。

錯項一

看到等號即可假設所有值永不含空白。

錯項二

永遠採第一個 user，無須寫入規格。

完成獨立任務後再展開參考成果
  • 引號內 needs review 視為單一 note 值，不以中間空白切割。
  • 重複 user 依本練習保留為陣列並產生警告，不猜哪個才是真實身分。
  • 缺值保留空值狀態；未知 zone 保留原文與未知欄，以利版本漂移調查。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
