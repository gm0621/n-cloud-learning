LESSON 05 · SNMP

判讀設備與介面
是否健康

SNMP 讓監控系統定期取得設備狀態與計數器。這一課不背 OID，而是先分清 Gauge、Counter、介面狀態與錯誤趨勢。

本課目標
  1. 分辨狀態值與累積計數器
  2. 判讀設備與介面健康
  3. 用前後差值解釋 Counter
建議時間：約 45–55 分鐘

本課章節

01 SNMP 回答什麼02 健康指標03 Gauge 與 Counter04 介面案例05 健康實作06 Counter 實作07 學習紀錄

01

SNMP 像設備的定期健康檢查

監控端定期讀取 CPU、記憶體、介面流量、錯誤與運作狀態。單一數值只是一個時間點，趨勢與前後差值才更有意義。

今天的問題
「使用者說網路斷斷續續，設備 CPU 卻只有 35%，還能看哪裡？」

CPU 正常只排除一種可能。還要查看上行介面利用率、錯誤／丟棄是否增加，以及介面是否頻繁 Up／Down。

核心觀念

設備健康不能只看一個紅綠燈。資源、介面負載、錯誤與狀態必須放在同一時間窗比較。

02

四組常用健康指標

CPU

處理負載

短暫高峰不一定有問題；持續高檔且伴隨服務異常才值得優先調查。

MEM

記憶體使用

查看持續成長、可用量與設備特性，不只看單次百分比。

TRAFFIC

介面利用率

需搭配介面速率與方向，判斷是否接近容量。

ERROR

錯誤與丟棄

看一段時間內是否持續增加，以及是否和使用者症狀同步。

03

Gauge 看目前值，Counter 看增加量

Gauge／狀態值

像 CPU 92%、溫度 48°C、介面目前 Up。可直接描述當下，但仍需時間趨勢。

Counter／累積計數

像總 Bytes、總錯誤數。數字通常只增不減；要用兩次取樣的差值解讀期間新增量。

錯誤 Counter13:00 = 1,240 → 13:05 = 1,300

五分鐘新增 60 筆錯誤，不是「剛剛發生 1,300 筆」。

設備重啟或 Counter 回繞可能讓數值下降。遇到負差值時，先查設備運作時間與計數器型態。

04

介面狀態要同時看 Admin 與 Oper

教學模擬介面狀態組合，不代表真實 N-Cloud 欄位名稱
AdminOper常見解讀下一步
