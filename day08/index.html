LESSON 08 · TOPN / REPORT / DASHBOARD

不是把圖放滿，
而是讓圖回答問題

TopN 找排名、趨勢圖看變化、報表保留固定期間結果、Dashboard 支援值班判斷。這一課練習選對指標、維度與呈現方式。

本課目標
  1. 分辨指標與維度
  2. 為問題選 TopN、趨勢或明細
  3. 設計能在一分鐘內判讀的 Dashboard
建議時間：約 60–75 分鐘

本課章節

01 圖表先有問題02 指標與維度03 TopN04 報表05 Dashboard06 模擬案例07 實作一08 實作二09 排錯10 學習紀錄

01

先寫一句問題，再選圖

「做一張漂亮 Dashboard」不是需求；「值班人員能在一分鐘內看出哪個分公司頻寬最接近飽和」才是。

本課故事
主管問：「台中分公司早上網路慢，是誰用了最多流量？現在還慢嗎？」

前半句適合 TopN，後半句需要趨勢或即時狀態；同一張排行不能回答所有問題。

完成判準

每個元件都必須能接回一個問題、時間範圍、指標與維度；不能回答問題的圖就刪掉。

02

指標是算什麼；維度是按什麼分組

指標 Metric

Bytes、Sessions、事件筆數、CPU%、延遲、遺失率。它決定比較的量。

維度 Dimension

來源 IP、目的 IP、Port、設備、介面、帳號。它決定每一列代表誰。

問題拆解哪個來源 IP（維度）的 Bytes（指標）最高？

如果把 Sessions 當成 Bytes，會把連線多但資料少的對象誤認為最大流量。

03

TopN 是排名，不是原因

TOP SOURCE

誰送得最多

以來源 IP 或網段分組，依 Bytes 排序。

TOP DESTINATION

資料去了哪裡

展開目的 IP、Domain 或服務。

TOP SERVICE

什麼服務占比高

依 Port／Protocol 或已辨識服務分組。

TOPN × TOPN

先找誰，再看去哪

先鎖定主要來源，再展開其主要目的。

排名第一只代表在指定期間與指標下最高。是否合理，還要看資產角色、排程、歷史基準與服務用途。

04

報表是可重現的期間快照

1讀者誰需要它
2期間日、週、月與時區
3內容排行、趨勢、明細
4驗證抽查原始查詢
排程前先手動驗證

先確認時間、欄位、單位與內容，再考慮排程；避免固定寄出一份人人看不懂或資料錯位的報表。

05

值班 Dashboard 的閱讀順序

上層

現在有沒有問題

重大告警、服務可用性、關鍵設備狀態。

中層

問題在哪裡

分公司、設備、介面、服務的排行與趨勢。

下層

下一步查什麼

可跳回查詢的條件、時間與來源。

實際元件名稱與可用操作依 N-Cloud 版本、權限與資料源而異。本課教的是設計邏輯，不虛構固定選單。

06

同一批 Flow，換指標會得到不同答案

教學模擬 Flow 彙總｜09:00–10:00，不代表真實 N-Cloud 報表格式
來源 IPBytesSessions主要目的資產角色
192.0.2.1518.4 GB42Backup-DC備份伺服器
192.0.2.886.2 GB8,420Web-CDN代理伺服器
192.0.2.312.1 GB310Microsoft-365一般端點
詳解

依 Bytes 排名，備份伺服器第一；依 Sessions 排名，代理伺服器第一。兩者都正確，但回答不同問題。還要比對備份排程，才能判斷 18.4 GB 是否異常。

動手練習 · 約 18 分鐘

實作二：設計三格值班 Dashboard

哪組最適合調查「分公司網路慢」？

尚未答對

G2 可逆 LAB

建立自己的測試版面

  1. 先寫出三個問題，再各選一個元件。
  2. 所有物件使用 `Gimmy-LAB-` 前綴。
  3. 固定同一時區與期間，避免圖表互相比錯。
  4. 逐格寫下指標、維度與驗收答案。
  5. 完成後刪除或依 LAB 規範保留。

驗收：一分鐘內能回答現在是否異常、在哪裡、下一步查什麼。

09

排錯：圖表怪怪的先查四件事

時間不一致

確認各元件期間、時區、更新頻率與資料延遲。

單位不同

Bytes／bits、平均／最大值、總量／速率不能混比。

分組錯誤

檢查來源／目的、設備／介面、IP／帳號等維度。

權限或空資料

回到原始查詢確認有資料、角色可見且條件一致。
