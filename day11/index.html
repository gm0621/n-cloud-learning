LESSON 11 · SECURITY INVESTIGATION

告警是起點，
時間線才是調查

資安事件調查要回答誰、從哪裡、何時、做了什麼、影響什麼。這一課用去識別模擬資料練習交叉驗證，不把一次登入或情資命中直接當成入侵結論。

本課目標
  1. 分辨告警、證據與結論
  2. 重建帳號與來源 IP 的活動時間線
  3. 判定影響範圍並提出保全與應變下一步
建議時間：約 75–90 分鐘

本課章節

01 調查問題02 Triage03 事實與推測04 身分與來源05 模擬時間線06 實作一07 實作二08 排錯09 學習紀錄

01

先問需要做哪一個決定

是誤報、需觀察、需停用帳號，還是必須立即隔離？不同決定需要不同強度的證據與授權。

本課事件
09:22，帳號 amy 從外部 IP 203.0.113.45 登入成功；系統同時出現「異常來源」告警。

這是一個值得調查的訊號，但還不能直接寫成「amy 帳號遭入侵」。

安全邊界

本課 IP 使用文件保留網段，資料完全為教學模擬；真實調查不得把帳號、IP、檔名或個資貼到公開教材。

02

五分鐘 Triage 先保留最重要資訊

1時間首次、最後、時區
2身分帳號、角色、資產
3來源IP、位置、設備
4行為成功、失敗、通聯、變更
第五項影響與急迫性

特權帳號、持續活動、敏感資產或資料外傳跡象會提高優先級。

03

把每一句話標成三類

事實

09:22:14 有一筆 amy 從指定來源登入成功的紀錄。

推測

來源和平常不同，可能是帳號被盜，也可能是使用者出差或 VPN 出口改變。

待確認

amy 當時是否本人操作、來源是否公司核准、MFA 是否成功。

用詞要準確

寫「觀察到」「支持」「未發現」；避免在證據不足時寫「已證明」「一定」「完全沒有」。

04

同一帳號不一定等於同一人

ACCOUNT

帳號情境

角色、權限、正常時段、平常來源與最近變更。

SOURCE

來源情境

IP 歸屬、公司 VPN、雲端服務、歷史活動與情資品質。

AUTH

認證情境

成功／失敗、MFA、裝置、連續嘗試與鎖定。

AFTER

登入後行為

目的資產、資料量、管理操作與設定異動。

05

同一來源，登入前後發生了什麼

教學模擬 Syslog／Flow｜IP 為文件保留網段，不代表真實 N-Cloud 畫面
時間資料觀察判讀
09:18:03Syslogamy／203.0.113.45 登入失敗一次失敗，不足以判定攻擊
09:18:31Syslogamy／203.0.113.45 登入失敗需確認密碼或 MFA
09:22:14Syslogamy／203.0.113.45 登入成功，MFA success認證成功，但來源仍需確認
09:24:50FlowVPN IP → ERP:443，32 MB符合一般 ERP 使用的可能
09:27:11Syslogamy 查詢報表，無管理變更目前未見提權或設定異動
09:31:08Syslogamy 登出活動約九分鐘
詳解

現有證據顯示 MFA 成功、登入後存取 ERP 且無管理變更，降低立即入侵的可信度；仍需向 amy 確認本人操作與來源位置。不能只因情資標記就跳過身分確認。

07

動手練習 · 約 20 分鐘

實作二：擴大範圍但不要撈全部

下一輪搜尋最合理的是？

尚未答對

G1 調查實作

完成一頁事件紀錄

  1. 寫明事件 ID、時區、調查時間範圍與資料保存位置。
  2. 列出事實、推測與待確認，各至少兩項。
  3. 建立帳號與來源兩個搜尋方向。
  4. 記錄影響範圍與尚未觀察到的高風險行為。
  5. 提出需授權的應變，不自行停用帳號或封鎖 IP。

驗收：紀錄足以讓第二位調查者重現，且不洩漏到公開位置。

08

排錯：資安調查常見陷阱

時鐘不一致

保留原始時間與時區，換算後再合併時間線。

IP 被多人共用

NAT、Proxy、VPN 出口不能直接等同單一使用者。

情資過期或誤判

記錄來源、更新時間與信心，不以單一分數定罪。

證據可能被覆寫

先依規範保全原始查詢、匯出與雜湊，再進行變更。
