02

先備能力與三個本課概念

開始前先確認
  • 能區分網路與應用量測層次
  • 能使用 localhost 虛構測試端點
  • 了解逾時頻率與停止條件
Ping 證據界線

Ping 可觀察 ICMP 往返與遺失，但不能證明 TCP 服務或完整應用交易成功。

別混淆：Ping 成功不等於網站、登入或資料庫皆正常。

Port 連線測試

Port 測試驗證指定傳輸端點可建立連線，仍不保證上層協定回應正確。

別混淆：TCP 連線成功不能直接代表使用者交易成功。

Web 交易量測

Web 測試可檢查 HTTP 狀態、內容與時間，但結果只代表該測點與路徑。

別混淆：單一測點成功不能外推所有地區與所有使用者。

05

跟著做：每一步都有預期與失敗訊號

1

先寫使用者症狀與量測位置

輸入：登入失敗、單一 LAB 測點與觀察期間

預期：問題限定為該測點到登入路徑的可用性

證據：症狀、測點、期間與未知使用者範圍

失敗：未指定測點便聲稱所有使用者受影響

2

依層次設計三種最小測試

輸入：localhost、TCP 443、兩條虛構 HTTPS 路徑

預期：每項測試都有頻率、逾時與成功條件

證據：測試契約記錄目標及可證明範圍

失敗：把三項測試都寫成網站是否正常

3

依序判讀 fixture 的結果

輸入：Ping、Port、登入與健康路徑四列結果

預期：定位到登入交易層而非基本可達性

證據：分層時間線保留 HTTP 狀態與延遲

失敗：因 Ping 和 Port 成功便忽略 HTTP 503

4

清理測試並確認沒有殘留

輸入：LAB 物件清單與建立前基準數量

預期：刪除後三類測試物件都回到基準

證據：建立、觀察、刪除與最終計數紀錄

失敗：留下高頻測試或改測外部未核准目標

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

本課專屬排錯

Ping 失敗但 Web 測試成功

最小檢查：核對 ICMP 政策、測點、名稱解析與快取

預期：確認不同協定可能有不同允許策略

修正：保留兩項事實並改用適合的可達性旁證

停止／升級：不得為測試擅自放寬網路政策

Port 成功而 Web 回應逾時

最小檢查：比較連線時間、TLS、HTTP 路徑與後端等待

預期：可把傳輸建立與上層交易時間分開

修正：加入受控健康路徑與應用紀錄對照

停止／升級：需要改服務設定時轉交核准變更流程

刪除後仍持續出現測試結果

最小檢查：檢查排程、重試佇列與其他同名 LAB 物件

預期：所有產生來源停止且計數回到基準

修正：停用核准 LAB 排程並依索引逐項清除

停止／升級：無法識別來源時立即升級平台管理者

來源、版本與複核狀態

  • RFC 792 Internet Control Message Protocol｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-22｜適用：ICMP Echo 的協定證據界線
  • RFC 9110 HTTP Semantics｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-22｜適用：HTTP 狀態碼與語意基礎
  • N-Cloud PM Ping Web Port 之當期受控說明｜CONTROLLED_SOURCE_REQUIRED｜複核：UNKNOWN｜適用：產品測試能力、欄位、頻率限制與清理

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。

教師版與錯項解析

案例答案

網路與 TCP 可達，但應用交易失敗；需查 Web／後端證據。

錯項一

Ping 成功代表網站完全正常。

錯項二

443 可連代表登入交易成功。

完成獨立任務後再展開參考成果
  • Ping 12 ms 與 TCP 443 成功，只能證明基本網路與傳輸連線可達。
  • 登入路徑回 HTTP 503，而健康路徑回 200，問題應先聚焦登入交易依賴。
  • 結論只適用 LAB 測點；刪除所有測試物件並確認回到原基準。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
