Q04公司單位與 IP 對應Home／Domain 與三個單位網段需補強

我的原答案

建立四組網段並啟用流量分析。

同事實機頁

四組 CIDR 相同，並明確在 Home 與三個子網段都勾選「啟用 Flow 分析」。

考試建議答案

Domain 對應目前領域的 Home；三個子網段另外新增。每筆都要把 CIDR 加入下方清單並儲存，不能只留在輸入框。

逐步設定

位置：系統管理 → IP 名稱解析 → IP 名稱解析列表

項目名稱／網段Flow
公司整體目前領域的 Home／192.168.0.0/16啟用
主機網段192.168.1.0/24啟用
OA 網段192.168.2.0/23啟用
訪客網段192.168.4.0/23啟用
  1. 先搜尋目前領域名稱，找到帶 Home 圖示的公司整體項目；不要另外新增一筆字面名稱為「Domain」的普通網段。
  2. 勾選該列的編輯欄並按鉛筆，確認「啟用 Flow 分析」已勾選。
  3. 在「單一 IP 或網段」輸入 192.168.0.0/16，按加號；確認它已出現在「網段定義」清單。
  4. 回列表按上方加號，新增「主機網段」，勾選 Flow 分析，加入 192.168.1.0/24。
  5. 用相同方式新增「OA網段」，加入 192.168.2.0/23；不可誤填成 /24。
  6. 新增「訪客網段」，加入 192.168.4.0/23。
  7. 每一筆按右下角「確定」儲存，再回列表逐筆重開核對。

驗收

  • 列表可找到 Home、主機、OA、訪客四組定義。
  • 四組 CIDR 完全符合題目，Flow 欄皆為啟用。
  • 後續查詢可用名稱解析顯示「主機網段／OA網段／訪客網段」。

常見錯誤

  • 「啟用 Flow 分析」不是「啟用 IP 名稱解析分享」。
  • 公司 /16 與三個子網段重疊；若顯示錯誤單位，再檢查呈現優先權，題目未指定的數字不要亂填。
  • 正式環境若 Home 已有其他網段，先核對再修改，避免誤刪既有範圍。
Q05公司內對外流量即時監控Flow · Home → !Home一致

共同答案

Flow、來源 Home、目的 !Home、Byte／速率、時間單位 1 分鐘內。

排名欄位

來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析；排序數值 Byte。

容易填錯

「公司內對外流量即時監控」是整份分時監控報表名稱，不是 Top N 子項名稱。

逐步設定

位置：報表 → 分時監控報表 → 訂製分時監控報表

欄位設定值
製作依據Flow
來源 IPHome（新增／包含）
目的 IPHome（忽視／排除），形成 !Home
統計Byte、曲線圖、速率
Top N 排序來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析
排序數值Byte
時間單位1 分鐘內
  1. 在「報表製作依據」選 Flow。
  2. 開啟「IP 過濾－來源 IP」，在 IP 名稱解析選目前領域的 Home，按加號「新增」，再按確定。
  3. 開啟「IP 過濾－目的 IP」，同樣選 Home，但按驚嘆號「忽視」；清單應顯示 [!]Home。
  4. 回主畫面確認方向為 Home → !Home，不要再手動疊加 192.168.0.0/16。
  5. 在分時監控報表設定按加號，選 Byte、曲線圖、計算方式「速率」。
  6. 打開「分時監控 Top N」，新增子項「內對外流量排名」，移除預設欄位，再依序加入四個指定排名欄位，排序數值選 Byte。
  7. 按右上角磁碟圖示「儲存查詢條件」，正式名稱填「公司內對外流量即時監控」，時間單位選「1 分鐘內」。
  8. 考試正式設定時按「確定」儲存並啟用；若只練習，先選停用，避免產生告警。

驗收

  • 重新開啟已儲存報表，方向仍是 Home → !Home。
  • 即時圖表有 Bytes 速率曲線，Top N 有四欄與數值。
  • 用一台內部主機產生對外流量後，排名能出現來源與目的。

常見錯誤

  • [!] 才表示排除；目的若選「新增」就變成內對內。
  • Top N 子項名稱不能代替整份報表名稱。
  • Top N 切成 ON 但未儲存，仍不算完成。
Q06情資 IP 連線排名Syslog · !Home → Home · 日報表需修正

我的原答案問題

寫成 Flow／連線事件太寬。

修正後

Syslog、!Home → Home、啟用情資比對、Hit Count、日報表。

最終答案

排名欄位為來源 IP、目的 IP、目的 IP 名稱解析；最後一欄用來呈現目的 IP 所屬單位。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值
製作依據Syslog
來源 IP!Home
目的 IPHome
情資比對啟用比對
排序依據來源 IP、目的 IP、目的 IP 名稱解析
排序數值Hit Count
報表型態只勾日報表
  1. 製作依據選 Syslog；資料來源必須是會記錄連線行為的設備日誌。
  2. 查詢條件選「情資比對」，設為「啟用比對」；題目未指定情資類型或評分，不要自行加門檻。
  3. 「IP 過濾－來源 IP」選 Home 後按「忽視」，形成 !Home。
  4. 「IP 過濾－目的 IP」選 Home 後按「新增」，形成外對內。
  5. 移除預設排序欄位，加入來源 IP、目的 IP、目的 IP 名稱解析；排序數值選 Hit Count。
  6. 先查詢確認來源 IP 有情資標記，目的 IP 名稱解析能顯示第 4 題建立的單位。
  7. 按右上角「儲存查詢條件」，名稱填「情資IP連線排名」，報表型態只勾日報表；需要排程時再正式儲存。

驗收

  • 結果方向是外部來源到內部目的。
  • 來源 IP 確實命中情資，不是只因啟用比對就假設命中。
  • 日報表產出後包含三個指定欄位及 Hit Count。

常見錯誤

  • 不要選 Flow，也不要用 Byte 排名。
  • 「24 小時內」只是查詢視窗，不等於已設定日報表。
  • 目的 IP 名稱解析依賴第 4 題；若空白，先修正名稱解析。
Q07檔案伺服器讀取資料排名來源使用者 · Byte · 日報表需補強

共同答案

Syslog、讀取事件、來源使用者、Byte、日報表。

示範限制

同事畫面用其他 NAS；考試仍要選題目指定的 192.168.11.100。

完成條件

日誌中的 read／File、來源使用者與 Bytes 都必須真的有值；Hit Count 不能代替讀取檔案大小。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值
製作依據Syslog
設備題目指定的 Synology File Server 192.168.11.100
事件關鍵字read
狀態File，完全匹配
排序依據來源使用者
排序／顯示數值Byte
報表型態只勾日報表
  1. 先到事件查詢抽看題目 NAS 的實際稽核日誌，確認讀取事件解析為 read、狀態為 File，並有來源使用者及 Bytes。
  2. 進入 Top N 報表，製作依據選 Syslog。
  3. 查詢條件選「設備」，展開 Global，勾選 192.168.11.100；不要用來源 IP 代替設備。
  4. 事件關鍵字填 read；狀態填 File 並選完全匹配。
  5. 排序依據只保留「來源使用者」，排序數值與數值顯示都選 Byte。
  6. 執行短時間查詢，確認帳號與 Bytes 不是空值或 0。
  7. 儲存名稱填「公司檔案伺服器讀取資料排名」，報表型態只勾日報表。
  8. 若要調閱離職前三個月，另切換「起迄時間」，以實際離職日回推三個月，並加入實際離職帳號；這和每日報表是兩個操作。

驗收

  • 排名以帳號彙總，數值單位為 Byte。
  • 抽一筆結果能看到設備、read／File、來源使用者及 Bytes。
  • 日報表可重新開啟，名稱與排程正確。

常見錯誤

  • 不同品牌／Windows 日誌未必使用 read／File，先看真實日誌再套條件。
  • 把檔案路徑加入分組會將同一帳號拆成多筆。
  • 事件數不等於檔案大小；Bytes 缺值時不能改用 Hit Count 冒充。
Q08外部 IP 對主機網段資料下載!Home → 192.168.1.0/24 · 完整日曆日需補強

共同答案

來源 !Home、目的 192.168.1.0/24，使用攻擊當日完整日曆日。

示範狀態

同事曾開啟事件下載表單但未下載，暫存條件已刪除。

資料範圍

Syslog 與 Flow 是不同來源；如果「所有連線」包含 Flow，需再建立一組同方向、同日期的 Flow 條件。

逐步設定

位置：事件 → 事件查詢；儲存後到 事件 → 已儲存查詢條件

欄位設定值
資料來源Syslog（記錄連線的設備日誌）
來源 IP!Home
目的 IP192.168.1.0/24
時間實際攻擊日 00:00:00～23:59:59
條件名稱外部IP對主機網段資料下載
  1. 選 Syslog，先確認所選設備日誌真的記錄連線；不要混入與連線無關的系統日誌。
  2. 「IP 過濾－來源 IP」選 Home 後按「忽視」，形成 !Home。
  3. 「IP 過濾－目的 IP」在單一 IP 或網段輸入 192.168.1.0/24 並加入；本題不是整個 Home。
  4. 時間切換成起迄時間，填實際攻擊日的 00:00:00 到 23:59:59；不要用「24 小時內」。
  5. 不加登入、情資、Port 或排名等題目未指定的限制，避免漏掉符合方向的事件。
  6. 按「儲存查詢條件」，名稱填「外部IP對主機網段資料下載」並儲存。
  7. 到「已儲存查詢條件」找到該列，按「事件下載」，再次核對日期；欄位樣版可維持 Default，匯出方式選直接下載。
  8. 按確定建立 CSV 匯出後，檢查檔案可開啟、時間欄與來源／目的 IP 都存在。
  9. 若還要涵蓋 Flow，另以 Flow 建立相同方向及日期的匯出，不能用 Syslog 檔案冒充。

驗收

  • 儲存條件可重新找到，名稱完全一致。
  • 下載檔不是空檔，最早與最晚事件都落在攻擊當日。
  • 抽樣事件皆為外部來源到 192.168.1.0/24。

常見錯誤

  • 用 Home 當目的會多匯出 OA、訪客等非主機網段。
  • 滾動 24 小時不等於完整日曆日。
  • 只看到下載表單但沒有產出檔案，不算完成。
Q09Web Server PM 連線品質監控80 分 OR 10 秒逾時一致

共同答案

Web Server PM monitor、URL https://192.168.11.121、80 分、Timeout 10 秒。

示範限制

同事未從設備資產樹完成關聯，也未啟用監控。

告警邏輯

效能分數低於 80 或 Web 請求逾時 10 秒即告警，兩者是 OR。

逐步設定

題目指定位置：設備管理 → 設備資產樹狀圖 → 找到 192.168.11.121 → Web 監控 → 新增

欄位設定值
類型Web
目標名稱Web Server PM monitor
監控 URLhttps://192.168.11.121
效能分數門檻80
Timeout Alert10 秒
連續逾時次數1 次
關聯設備192.168.11.121
  1. 先確認設備資產樹已有 192.168.11.121；沒有時回第 3 題完成納管，不能用其他設備代替。
  2. 展開該設備的 Web 監控並按新增，類型選 Web。
  3. 目標名稱填「Web Server PM monitor」；若系統自動移除空白，只要辨識一致即可。
  4. URL 填 https://192.168.11.121，確認沒有多餘空格。
  5. 選擇負責發出探測的監控設備；它和被監控 URL 不是同一概念。
  6. 打開「監控樣版與門檻值設定」，效能分數填 80。
  7. 勾選 Timeout Alert，秒數填 10，連續逾時次數填 1。
  8. 指定有效的告警通報服務／收件群組，儲存後將監控切為啟用。

驗收

  • 設備資產樹下可看到此 Web 監控，狀態為啟用。
  • 正常時能取得分數與回應時間，而不是持續 Unknown。
  • 在 LAB 暫時阻擋連線或使用測試 URL，確認逾時後真的產生告警；測完恢復。

常見錯誤

  • 從「效能監控列表」新增但未關聯設備，不符合題目指定入口。
  • 80 分與 10 秒不是 AND。
  • 未指定通報服務時，即使觸發門檻也可能只有系統事件、沒有通知。

版本差異：若考場畫面只有「效能監控 → Web 監控」，先完成相同欄位，再回設備資產樹確認關聯；以資產樹中看得到為驗收標準。

Q10SSL-VPN 登入行為監控18:00～隔日 08:00 · 一筆門檻需補強

共同答案

Syslog、成功＋失敗、18:00～08:00、Hit Count 1，帶出帳號。

實機補充

課程範例是應用服務 ssl-web、分類 vpn，帳號欄為來源使用者。

先做資料確認

ssl-web／vpn 只是此版本範例；必須先抽看考場 Fortigate 的成功與失敗日誌。

逐步設定

位置：報表 → 分時監控報表 → 訂製分時監控報表

欄位設定值
製作依據Syslog
應用服務／分類ssl-web／vpn，完全匹配（須先核對真實日誌）
稽核登入成功＋登入失敗
每日時段18:00～08:00，跨午夜
統計Hit Count、累計值、Red 門檻 1
告警1 分鐘內、連續 1 次
排名／詳細欄位來源 IP、來源使用者
  1. 先到事件查詢找一筆 SSL-VPN 成功與一筆失敗日誌，記下實際「應用服務、分類、稽核、來源使用者」值。
  2. 製作依據選 Syslog；應用服務、分類依實際值設定完全匹配。只有和範例一致時才填 ssl-web／vpn。
  3. 稽核條件同時勾「登入成功」與「登入失敗」，不要勾登出。
  4. 時間範圍填 18:00、08:00，按加號加入；確認清單保持 18:00–08:00，不是反向的 08:00–18:00。
  5. 新增 Hit Count 統計，計算方式選累計值，啟用門檻，Red 填 1。
  6. 開啟分時監控 Top N，加入來源 IP、來源使用者，排序數值選 Hit Count。
  7. 在詳細告警事件欄位加入「來源使用者」，確保通知能帶出帳號。
  8. 儲存名稱填「SSL-VPN登入行為監控」，時間單位選 1 分鐘內，連續高於門檻值選 1 次。
  9. 指定告警通報服務與收件群組，儲存並啟用。

驗收

  • 在 LAB 於下班時段各產生一次成功與失敗登入，兩者都能命中。
  • 告警詳細資料可看到實際來源使用者帳號。
  • 白天 08:00～18:00 的同類事件不應觸發此時段告警。

常見錯誤

  • 只勾成功或只勾失敗會漏報。
  • 來源 IP 不能取代來源使用者。
  • 門檻 1 代表一筆達門檻，不代表通知零延遲。
Q11SSL-VPN 登入日誌轉發192.168.11.110 · UDP 514需補強

共同答案

承接第 10 題，在 Hit Count 統計組啟用 Syslog relay，送到 192.168.11.110:514。

待核對

表單沒有協定欄；題目要求 UDP，必須用版本文件或封包確認。

驗收原則

Port 514 不等於已證明 UDP；接收端收到符合第 10 題的封包才算完成。

逐步設定

位置：承接第 10 題訂製分時監控報表 → 編輯 Hit Count 統計組 → Syslog relay

欄位設定值
來源條件第 10 題完整 SSL-VPN 登入條件
Syslog relay勾選
目的 IP192.168.11.110
Port514
協定UDP（表單未顯示，需另驗）
  1. 先完成並儲存第 10 題，確認 SSL-VPN 成功／失敗事件能命中。
  2. 重新編輯「SSL-VPN登入行為監控」，進入 Hit Count 統計組；不要誤進整份報表的告警通報服務。
  3. 勾選 Syslog relay。
  4. Relay IP 填 192.168.11.110，Port 填 514。
  5. 若版本提供協定選項，明確選 UDP；若沒有，先查該版本 relay 的實作或設定。

  7. 在 192.168.11.110 啟動接收服務或封包擷取，於 LAB 產生一筆符合條件的 SSL-VPN 登入事件。

驗收

  • 接收端可看到來源為 N-Cloud、目的 Port 514 的 UDP 封包。
  • 收到的內容對應本次 SSL-VPN 登入，而不是其他 Syslog。
  • 重開報表後 relay IP／Port 仍存在。

  • 只填表未儲存，接收端不會有資料。
  • 把「Syslog 告警通報服務」誤當 Hit Count 的事件 relay。
  • 未取得 UDP 證據前，狀態只能標「待核對」。
Q12外對內重要服務 Port 排名五種服務 · 六個排名欄位一致

共同條件

Syslog、!Home → Home、Hit Count；五個目的 Port 是 OR 集合。

六個排名欄位

來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析、目的 Port、目的 Port 解析。

容易填錯

要選目的 Port，不是來源端臨時 Port；LDAP 依題目使用 389，不用 636 取代。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值
製作依據Syslog
來源／目的!Home → Home
目的服務telnet、ssh、windows-remote-desktop、ms-sql-server、ldap
標準 Port23、22、3389、1433、389
排序欄位來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析、目的 Port、目的 Port 解析
排序數值Hit Count
  1. 製作依據選 Syslog，確認設備日誌有來源／目的 IP 與目的 Port。
  2. 來源 IP 選 Home 後按「忽視」，形成 !Home；目的 IP 選 Home 後按「新增」。
  3. 打開「Port 過濾－目的 Port」，依序加入 telnet、ssh、windows-remote-desktop、ms-sql-server、ldap。
  4. 核對這五個名稱解析在考場仍對應 23、22、3389、1433、389；若被自訂，應以題目 Port 為準。
  5. 移除預設排序欄位，依題目順序加入六個欄位。
  6. 排序數值選 Hit Count，執行短時間查詢檢查欄位是否有值。
  7. 按儲存查詢條件，名稱填「公司外對內部重要服務port 連線排名」；題目未要求日報表，不自行加排程。

驗收

  • 結果每筆都是外部來源、內部目的與五個指定 Port 之一。
  • 六個欄位都顯示，目的 Port 解析能對上服務名稱。
  • 重新開啟報表後，五個 Port 與六個欄位沒有遺失。

常見錯誤

  • 五個 Port 是 OR，不是要求一筆事件同時滿足五個 Port。
  • 來源 Port 通常是臨時 Port，選錯會得不到題目結果。
  • Hit Count 是日誌筆數，不保證等於去重後的連線 Session。
Q13公司員工瀏覽外部網站排名目的主機名稱 · Hit Count需補強

共同答案

內對外，以「目的主機名稱」呈現外部網站。

實機補充

Syslog、Home → !Home、HTTP／HTTPS、Hit Count。

完成條件

結果必須真的顯示外部網站 FQDN；若只有 IP，先修資料收集，不要把來源主機名稱拿來代替。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值
製作依據Syslog（需含網站名稱）
來源／目的Home → !Home
目的 Porthttp、https（常見 80／443）
排序依據目的主機名稱
排序／顯示數值Hit Count
報表名稱公司員工瀏覽外部網站排名
  1. 先在事件查詢抽看 Web／Proxy／Fortigate 日誌，確認「目的主機名稱」欄能看到外部 FQDN。
  2. 進入 Top N，製作依據選 Syslog。
  3. 來源 IP 選 Home 並新增；目的 IP 選 Home 後按忽視，形成 Home → !Home。
  4. 目的 Port 加入 http、https；若環境有 Proxy 或非標準 Web Port，先依實際日誌判斷是否需補充。
  5. 排序依據只選「目的主機名稱」，排序數值與顯示數值選 Hit Count。
  6. 執行查詢，確認結果是網站 FQDN，而不是來源電腦名稱、設備名稱或全空白。
  7. 儲存名稱填「公司員工瀏覽外部網站排名」；題目未要求日報表，不額外設定排程。

驗收

  • 開啟幾個測試網站後，排名能看到目的網站名稱與次數。
  • 抽樣事件方向為內對外，目的 Port 符合 Web 流量。
  • 結果不把同一個內部來源主機名稱誤當外部網站。

常見錯誤

  • 選「來源主機名稱」會變成員工電腦排名。
  • 只有 DNS 解析不一定能代表實際瀏覽；應以 Web／Proxy／TLS 日誌欄位為準。
  • HTTPS 若未提供 SNI／Host 等資料，目的主機名稱可能為空，需先補資料來源。
Q14資安與服務監控戰情儀表板五個指定元件一致

五個元件

  • 公司對外流量
  • SSL-VPN 登入監控
  • 情資 IP 連線監控
  • 即時網路攻擊流量地球儀
  • 公司首頁連線監控

實機補充

地球儀可選「ATD 異常流量即時分析」；其他元件必須先有第 5、6、9、10 題的正式來源。

完成條件

五個元件都綁定正確資料來源且有資料。只有空的地球模型或未綁定卡片，不算完成。

逐步設定

位置：Dashboard → 列表 → 新增

題目元件應綁定來源
公司對外流量第 5 題「公司內對外流量即時監控」
SSL-VPN 登入監控第 10 題「SSL-VPN登入行為監控」
情資 IP 連線監控第 6 題「情資IP連線排名」
網路攻擊地球儀ATD 異常流量即時分析
公司首頁連線監控第 9 題 Web Server PM monitor
  1. 先確認第 5、6、9、10 題都已儲存、啟用且各自有資料；來源不存在時先回前題完成。
  2. 到 Dashboard 列表按新增，名稱可填「公司資安與服務監控戰情儀表板」。
  3. 加入流量／Top N 類元件，標題填「公司對外流量」，資料來源選第 5 題報表。
  4. 加入監控元件「SSL-VPN登入監控」，綁定第 10 題，確認能顯示命中數或最近告警。
  5. 加入 Top N 元件「情資IP連線監控」，綁定第 6 題日報表或可用的即時查詢來源。
  6. 加入地球儀元件，標題填「即時網路攻擊流量」，資料來源選「ATD 異常流量即時分析」，明細選 ATD 明細，範圍選全部，時間可先選 1 小時。
  7. 加入 Web／PM 元件「公司首頁連線監控」，綁定第 9 題 Web Server PM monitor。
  8. 調整版面，讓五項在第一個 Dashboard 畫面都可辨識；逐一按預覽檢查標題與來源。
  9. 儲存 Dashboard，離開後從列表重新開啟，確認配置與綁定沒有遺失。

驗收

  • 五個元件都在，標題不混淆且資料來源正確。
  • 流量、VPN、情資、Web PM 至少能看到最近數值／狀態。
  • 地球儀有 ATD 攻擊事件線條或數值；若沒有，需確認 ATD 資料與地理資訊，不可只看模型。
  • 重新登入或重新開啟 Dashboard 後仍完整。

常見錯誤

  • 用別人的既有報表替代自己前題建立的來源，名稱相似但條件可能不同。
  • 元件已拖入但未選資料來源，畫面存在不等於功能完成。
  • 「1 小時」是顯示資料區段，不代表更新頻率已驗證。
