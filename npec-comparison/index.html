Q04公司單位與 IP 對應Home／Domain 與三個單位網段需補強

我的原答案

建立四組網段並啟用流量分析。

同事實機頁

四組 CIDR 相同，並明確在 Home 與三個子網段都勾選「啟用 Flow 分析」。

考試建議答案

Domain 對應目前領域的 Home；三個子網段另外新增。每筆都要把 CIDR 加入下方清單並儲存，不能只留在輸入框。

逐步設定

位置：系統管理 → IP 名稱解析 → IP 名稱解析列表

項目名稱／網段Flow
公司整體目前領域的 Home／192.168.0.0/16啟用
主機網段192.168.1.0/24啟用
OA 網段192.168.2.0/23啟用
訪客網段192.168.4.0/23啟用
  1. 先搜尋目前領域名稱，找到帶 Home 圖示的公司整體項目；不要另外新增一筆字面名稱為「Domain」的普通網段。
  2. 勾選該列的編輯欄並按鉛筆，確認「啟用 Flow 分析」已勾選。
  3. 在「單一 IP 或網段」輸入 192.168.0.0/16，按加號；確認它已出現在「網段定義」清單。
  4. 回列表按上方加號，新增「主機網段」，勾選 Flow 分析，加入 192.168.1.0/24。
  5. 用相同方式新增「OA網段」，加入 192.168.2.0/23；不可誤填成 /24。
  6. 新增「訪客網段」，加入 192.168.4.0/23。
  7. 每一筆按右下角「確定」儲存，再回列表逐筆重開核對。

驗收

  • 列表可找到 Home、主機、OA、訪客四組定義。
  • 四組 CIDR 完全符合題目，Flow 欄皆為啟用。
  • 後續查詢可用名稱解析顯示「主機網段／OA網段／訪客網段」。

常見錯誤

  • 「啟用 Flow 分析」不是「啟用 IP 名稱解析分享」。
  • 公司 /16 與三個子網段重疊；若顯示錯誤單位，再檢查呈現優先權，題目未指定的數字不要亂填。
  • 正式環境若 Home 已有其他網段，先核對再修改，避免誤刪既有範圍。
Q05公司內對外流量即時監控Flow · Home → !Home需補強

原題能確定

Flow、來源 Home、目的 !Home，以及四個指定排名欄位。

本版實機示範

Byte、曲線圖、速率、1 分鐘與 Top N 子項名稱；表單尚未儲存或產生結果。

使用原則

先完成原題明文條件；Byte／速率／1 分鐘可作為本版即時監控建議值，但若考場表單或題目另有指定，應以實機為準。

逐步設定

位置：報表 → 分時監控報表 → 訂製分時監控報表

欄位設定值／證據層級
製作依據Flow（原題）
來源 IPHome（新增／包含，原題）
目的 IPHome（忽視／排除），形成 !Home（原題）
Top N 排序來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析（原題）
統計與排序數值Byte、曲線圖、速率（本版示範值）
時間單位1 分鐘內（本版示範值）
  1. 在「報表製作依據」選 Flow。
  2. 開啟「IP 過濾－來源 IP」，在 IP 名稱解析選目前領域的 Home，按加號「新增」，再按確定。
  3. 開啟「IP 過濾－目的 IP」，同樣選 Home，但按驚嘆號「忽視」；清單應顯示 [!]Home。
  4. 回主畫面確認方向為 Home → !Home，不要再手動疊加 192.168.0.0/16。
  5. 依序加入原題四個排名欄位；不要把示範中的子項名稱誤當原題必填名稱。
  6. 若考場沒有其他指定，可參照本版示範選 Byte、曲線圖、速率與 Byte 排序；這一步屬建議值。
  7. 正式名稱填「公司內對外流量即時監控」；時間單位可參照本版選 1 分鐘內，但須先確認考場要求。
  8. 按「確定」儲存並啟用後，再產生內對外流量驗證；未儲存示範不能算完成。

驗收

  • 重新開啟已儲存報表，方向仍是 Home → !Home。
  • 四個原題指定欄位都有值；若採本版示範，另確認 Bytes 速率曲線與 Byte 排序正常。
  • 用一台內部主機產生對外流量後，排名能出現來源與目的。

常見錯誤

  • [!] 才表示排除；目的若選「新增」就變成內對內。
  • Top N 子項名稱不能代替整份報表名稱。
  • Top N 切成 ON 但未儲存，仍不算完成。
Q06情資 IP 連線排名!Home → Home · 情資比對 · 日報表待實機確認

原題能確定

!Home → Home、啟用情資比對、三個指定排名欄位與日報表。

本版實機示範

製作依據 Syslog、排序數值 Hit Count；尚未查詢證明情資命中。

目前最有依據的方案

可先採 Syslog＋Hit Count，但要以查詢結果確認來源 IP 確實命中情資、目的 IP 名稱解析能呈現單位；不能把示範值寫成官方唯一答案。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值／證據層級
製作依據Syslog（本版示範，待查詢確認）
來源 IP!Home（原題）
目的 IPHome（原題）
情資比對啟用比對（原題）
排序依據來源 IP、目的 IP、目的 IP 名稱解析（原題）
排序數值Hit Count（本版示範）
報表型態只勾日報表（原題）
  1. 先確認可用資料來源真的記錄連線與情資欄位；本版實機示範選 Syslog。
  2. 查詢條件選「情資比對」，設為「啟用比對」；題目未指定情資類型或評分，不要自行加門檻。
  3. 「IP 過濾－來源 IP」選 Home 後按「忽視」，形成 !Home。
  4. 「IP 過濾－目的 IP」選 Home 後按「新增」，形成外對內。
  5. 移除預設排序欄位，加入來源 IP、目的 IP、目的 IP 名稱解析；若採本版示範，排序數值選 Hit Count。
  6. 先查詢確認來源 IP 有情資標記，目的 IP 名稱解析能顯示第 4 題建立的單位。
  7. 按右上角「儲存查詢條件」，名稱填「情資IP連線排名」，報表型態只勾日報表；需要排程時再正式儲存。

驗收

  • 結果方向是外部來源到內部目的。
  • 來源 IP 確實命中情資，不是只因啟用比對就假設命中。
  • 日報表產出後包含三個指定欄位；若採本版示範，另確認 Hit Count 有值。

常見錯誤

  • 未查詢真實結果前，就把 Syslog／Hit Count 當成原題唯一指定值。
  • 「24 小時內」只是查詢視窗，不等於已設定日報表。
  • 目的 IP 名稱解析依賴第 4 題；若空白，先修正名稱解析。
Q07檔案伺服器讀取資料排名檔案讀取 · 來源使用者 · Byte · 日報表需修正

目前實機畫面

查詢條件已有「稽核 → Windows 檔案分享 → 檔案讀取」，這就是中文版 Read，應優先使用。

同事 Synology 範例

使用事件關鍵字 read＋狀態 File，但設備不是題目指定的 192.168.11.100，且未查詢驗證。

修正後答案

先用標準化「檔案讀取」稽核條件；只有實際事件沒有此稽核值、但欄位確實顯示 read／File 時，才改用關鍵字方案。兩套條件不要同時疊加。排名仍是來源使用者＋Byte＋日報表。

逐步設定

位置：報表 → Top N → Top N 報表

欄位設定值
製作依據Syslog
設備題目指定的 Synology File Server 192.168.11.100
目前實機的讀取條件稽核 → Windows 檔案分享 → 檔案讀取
替代條件事件關鍵字 read＋狀態 File 完全匹配；僅於真實事件欄位相符時使用
排序依據來源使用者
排序／顯示數值Byte
報表型態只勾日報表
  1. 進入 Top N 報表，製作依據選 Syslog。
  2. 查詢條件選「設備」，展開 Global，勾選 192.168.11.100；不要用來源 IP 代替設備。
  3. 查詢條件選「稽核」，展開「Windows 檔案分享」，勾選「檔案讀取」。這個選項就是你這版的 Read。
  4. 不要在「動作」勾允許／不允許；那是允許或拒絕結果，不是檔案讀取。
  5. 先只套用「檔案讀取」執行短時間查詢，確認命中的事件有來源使用者與 Bytes。
  6. 如果完全沒有結果，再抽看題目 NAS 的原始事件；只有欄位確實為 read／File 時，才移除稽核條件，改用事件關鍵字＋狀態完全匹配。不要兩套同時使用。
  7. 排序依據只保留「來源使用者」，排序數值與數值顯示都選 Byte。
  8. 確認帳號與 Bytes 不是空值或 0，再儲存名稱「公司檔案伺服器讀取資料排名」，報表型態只勾日報表。
  9. 若要調閱離職前三個月，另切換「起迄時間」，依實際離職日回推三個月並指定離職帳號；這和每日報表是兩個操作。

驗收

  • 抽一筆結果能確認其稽核行為是「檔案讀取」，不是單純允許連線。
  • 排名以來源使用者彙總，數值單位為 Byte 且不是 0。
  • 日報表可重新開啟，名稱、條件與排程正確。

常見錯誤

  • 把「動作 → 允許」當作 Read，會混入其他允許事件。
  • 同時勾「檔案讀取」又填 read／File，可能因 AND 條件過窄而查不到資料。
  • 把檔案路徑加入分組會將同一帳號拆成多筆。
  • 事件數不等於檔案大小；Bytes 缺值時不能改用 Hit Count 冒充。
Q08外部 IP 對主機網段資料下載!Home → 192.168.1.0/24 · 完整日曆日待實機確認

共同答案

來源 !Home、目的 192.168.1.0/24，使用攻擊當日完整日曆日。

示範狀態

同事曾開啟事件下載表單但未下載，暫存條件已刪除。

資料範圍待確認

原題沒有指定 Syslog 或 Flow。先確認考場「訂製事件儲存條件」涵蓋的資料來源；只有規則或考場明確要求 Flow 時，才另建同方向、同日期的 Flow 匯出。

逐步設定

位置：事件 → 事件查詢；儲存後到 事件 → 已儲存查詢條件

欄位設定值／證據層級
資料來源Syslog（本版示範；是否涵蓋題目所稱所有連線待確認）
來源 IP!Home（原題）
目的 IP192.168.1.0/24（原題）
時間實際攻擊日 00:00:00～23:59:59（原題）
條件名稱外部IP對主機網段資料下載（原題）
  1. 先確認考場「訂製事件儲存條件」可選的資料來源；本版示範使用 Syslog，但原題沒有指定。
  2. 「IP 過濾－來源 IP」選 Home 後按「忽視」，形成 !Home。
  3. 「IP 過濾－目的 IP」在單一 IP 或網段輸入 192.168.1.0/24 並加入；本題不是整個 Home。
  4. 時間切換成起迄時間，填實際攻擊日的 00:00:00 到 23:59:59；不要用「24 小時內」。
  5. 不加登入、情資、Port 或排名等題目未指定的限制，避免漏掉符合方向的事件。
  6. 按「儲存查詢條件」，名稱填「外部IP對主機網段資料下載」並儲存。
  7. 到「已儲存查詢條件」找到該列，按「事件下載」，再次核對日期；Default 樣版與直接下載只是示範選項。
  8. 建立匯出後，檢查檔案可開啟、時間欄與來源／目的 IP 都存在。
  9. 只有在考場規則確認「所有連線」另含 Flow 時，才補做 Flow 匯出；不要把它預設成原題必填。

驗收

  • 儲存條件可重新找到，名稱完全一致。
  • 下載檔不是空檔，最早與最晚事件都落在攻擊當日。
  • 抽樣事件皆為外部來源到 192.168.1.0/24。

常見錯誤

  • 用 Home 當目的會多匯出 OA、訪客等非主機網段。
  • 滾動 24 小時不等於完整日曆日。
  • 只看到下載表單但沒有產出檔案，不算完成。
