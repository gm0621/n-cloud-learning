QUESTION BY QUESTION

第 4～14 題逐題比較

展開每題可看到「我的原答案」「同事實機頁」以及考試時建議採用的最終寫法。

Q04公司單位與 IP 對應Home／Domain 與三個單位網段需補強

我的原答案

建立 192.168.0.0/16、主機、OA、訪客網段並啟用流量分析。

同事實機頁

四組 CIDR 相同，並明確在 Home 與三個子網段上都勾選「啟用 Flow 分析」。

考試建議答案

Home／Domain 192.168.0.0/16、主機 192.168.1.0/24、OA 192.168.2.0/23、訪客 192.168.4.0/23；每一筆都核對 Flow 欄為啟用。「Flow 分析」不是「IP 名稱解析分享」。

Q05公司內對外流量即時監控Flow · Home → !Home一致

共同答案

Flow、來源 Home、目的 !Home、Byte／速率、時間單位 1 分鐘內。

排名欄位

來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析；排序數值 Byte。

容易填錯的地方

「公司內對外流量即時監控」要填在整份分時監控報表名稱，不能只拿 TopN 子項名稱代替。

Q06情資 IP 連線排名Syslog · !Home → Home · 日報表需修正

我的原答案問題

寫成「Flow／連線事件」太寬，沒有對到這版實機表單的精確資料來源與統計方式。

同事實機頁

Syslog、!Home → Home、啟用情資比對，以 Hit Count 排名，僅勾日報表。

修正後答案

排序欄位使用「來源 IP、目的 IP、目的 IP 名稱解析」。最後一欄用來呈現目的 IP 所屬單位；正式驗收還要確認實際命中情資的是來源 IP。

Q07檔案伺服器讀取資料排名來源使用者 · Byte · 日報表需補強

共同答案

Syslog、讀取事件、來源使用者分組、Byte 排名、日報表；不能用 Hit Count 代替讀取檔案大小。

同事示範限制

實機找不到題目指定的 192.168.11.100，因此使用另一台既有 Synology NAS 示範。

完成條件

考試要使用題目指定設備，並確認實際日誌中的 read／File、來源使用者與 Bytes 都有值。用其他 NAS 截圖只能證明操作方法，不能算正式完成。

Q08外部 IP 對主機網段資料下載!Home → 192.168.1.0/24 · 完整日曆日需補強

共同答案

來源 !Home、目的 192.168.1.0/24，指定攻擊當日 00:00:00～23:59:59，儲存指定名稱。

同事實機頁

示範 Syslog，開過事件下載表單但沒有下載；暫存條件之後已刪除。

資料範圍注意

Syslog 與 Flow 是不同資料來源。若稽查要求涵蓋所有 Flow，需另建相同方向與日期的 Flow 條件；不能把單一 Syslog 匯出稱為所有連線資料。

Q09Web Server PM 連線品質監控80 分 OR 10 秒逾時一致

共同答案

名稱 Web Server PM monitor，URL https://192.168.11.121，分數門檻 80，Timeout 10 秒、連續逾時 1 次。

同事示範限制

未找到題目 IP 的關聯設備，監控保持關閉，也未從設備資產樹完成新增。

告警邏輯

效能分數低於 80 或 Web 請求逾時 10 秒，是 OR，不是兩者同時發生才告警。需關聯題目設備並實際啟用，才能算完成。

Q10SSL-VPN 登入行為監控18:00～隔日 08:00 · 一筆門檻需補強

共同答案

Syslog、成功與失敗都納入、跨日 18:00～08:00、Hit Count 1、第一次即告警，並帶出登入帳號。

同事實機補充

課程範例使用應用服務 ssl-web、分類 vpn；帳號欄使用「來源使用者」。

正式驗收

ssl-web／vpn 是範例值，仍要先核對考場 Fortigate 的成功與失敗日誌解析結果。若真實欄位不同，應以實際日誌為準。

Q11SSL-VPN 登入日誌轉發192.168.11.110 · UDP 514需補強

共同答案

承接第 10 題條件，啟用 Syslog relay，目的 IP 192.168.11.110、Port 514、題目要求 UDP。

同事示範限制

表單只有 Relay IP 與 Port，沒有協定欄，也未實際啟用或傳送日誌。

驗收方式

不能因為 Port 是 514 就直接宣稱已確認 UDP。需查後端設定／版本文件，或在接收端用封包證據確認 UDP。

Q12外對內重要服務 Port 排名五種服務 · 六個排名欄位一致

共同條件

Syslog、!Home → Home、Hit Count，目的 Port 為 23、22、3389、1433、389，五者為 OR 集合。

六個排名欄位

來源 IP、來源 IP 名稱解析、目的 IP、目的 IP 名稱解析、目的 Port、目的 Port 解析。

容易填錯的地方

要選「目的 Port」，不是來源端的臨時 Port；LDAP 依題目使用 389，不用 LDAPS 636 取代。

Q13公司員工瀏覽外部網站排名目的主機名稱 · Hit Count需補強

共同答案

內對外流量，以「目的主機名稱」呈現外部網站，不用來源主機名稱或設備名稱代替。

同事實機補充

Syslog、Home → !Home、目的 Port HTTP／HTTPS，排序數值為 Hit Count。

完成條件

查詢結果必須真的顯示外部網站 FQDN。若目的主機名稱為空白或只有 IP，應先檢查 Web／Proxy／TLS 網站名稱資料是否被收集。

Q14資安與服務監控戰情儀表板五個指定元件一致

共同答案

  • 公司對外流量
  • SSL-VPN 登入監控
  • 情資 IP 連線監控
  • 即時網路攻擊流量地球儀
  • 公司首頁連線監控

同事實機補充

地球儀元件可選「ATD 異常流量即時分析」；但前面各題都未儲存為正式來源。

完成條件

先建立並驗證第 5、6、9、10 題的正式來源，再逐一綁定元件並確認有資料。只有地球模型、沒有攻擊線條或數值，不算完成驗收。

IMPLEMENTATION STATUS

「填過表單」不等於「完成題目」

分享或複習時，建議用下列四層證據判斷，不要只看截圖上是否有填值。

1. 條件已填

只證明欄位存在、值能輸入，尚未改變系統。

2. 已儲存／啟用

系統中能重新找到設定，狀態與題目要求相符。

3. 有實際結果

報表、監控、下載、轉發或 Dashboard 真的產生資料。

4. 驗收證據完整

指定設備、方向、欄位、時間、協定與結果都能逐項核對。
