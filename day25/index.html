02

先備能力與三個本課概念

開始前先確認
  • 能讀取去識別 Syslog 原文
  • 能進行整數除法與餘數計算
  • 了解來源分類不等於業務風險
PRI 編碼

PRI 以尖括號內整數表示 Facility 乘八再加 Severity，範圍需先驗證。

別混淆：PRI 不是單獨的嚴重度，也不是事件編號。

Header 與 Message

Syslog 訊息可分 PRI、版本與標頭欄位，再保留應用訊息或結構化資料。

別混淆：不同格式的欄位位置不可未核對就硬套。

Severity 界線

Severity 是來源設備提供的層級分類，需結合資產、行為與影響評估。

別混淆：數字較小或名稱緊急不自動等同業務事故優先級。

03

位置、版本與安全 Gate

候選入口｜必須以實機版本與角色核對設備管理 → 自定義資料格式；實際 parser 入口依版本核對

教材只固定工作目的與驗收證據，不把未核對的子選單、按鈕或欄位畫成真實 UI。

G0／G2

操作邊界

  1. G0 可用去識別樣本反覆練習。
  2. G1 只查詢、檢視與核准匯出。
  3. G2 僅在核准 LAB 建立可清理物件。
  4. 任何外送、正式來源、自動執行、升級或服務變更均須逐項 G3 Gate。

05

跟著做：每一步都有預期與失敗訊號

1

凍結原始樣本與字元編碼

輸入：四筆去識別 Syslog 與 UTF-8 編碼說明

預期：原文逐字保留且沒有真實設備識別

證據：樣本雜湊索引與遮罩檢查紀錄

失敗：只保留解析欄位而丟失原始 PRI

2

辨識 PRI 與訊息格式邊界

輸入：尖括號、版本、時間、主機與訊息候選欄位

預期：每筆 PRI 可定位且格式差異有標記

證據：原文位置標註與格式版本欄位

失敗：假設所有來源都具有完全相同標頭

3

計算 Facility 與 Severity

輸入：PRI 整數與除以八的商及餘數公式

預期：四筆計算結果與 fixture 完全一致

證據：逐筆算式而非只填最終名稱

失敗：把 Facility 與 Severity 的商餘對調

4

分開來源層級與業務判讀

輸入：解碼結果、虛構資產角色與影響待查欄

預期：每筆均標示分類事實與影響狀態

證據：沒有用 Severity 單獨決定處置優先級

失敗：Severity=2 便直接宣告重大資安事故

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

計算值超出合法候選範圍

最小檢查：確認 PRI 是否為整數、括號是否完整與原文是否截斷

預期：PRI 可解析且商餘符合編碼規則

修正：標記格式失敗並保留原文供來源端核對

停止／升級：不得用猜測值繼續正規化

時間後欄位整體向右錯位

最小檢查：先識別訊息採用的 Syslog 格式版本

預期：依實際格式找到正確標頭與訊息邊界

修正：為不同版本建立分支測試與明確 fallback

停止／升級：格式未知時只保留原文與 UNKNOWN

Severity 被當成處置優先級

最小檢查：檢查資產角色、實際影響與關聯行為是否存在

預期：來源分類與業務評估分欄呈現

修正：撤回過度結論並補最小影響查詢

停止／升級：需外部處置時先走事件核准流程

來源、版本與複核狀態

  • RFC 5424 The Syslog Protocol｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-22｜適用：PRI、Facility、Severity 與訊息結構
  • N-Cloud 自定義 Syslog 格式之當期受控說明｜CONTROLLED_SOURCE_REQUIRED｜複核：UNKNOWN｜適用：產品 parser 欄位、格式入口與版本行為

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。

案例答案

Facility=16、Severity=6；這是來源分類，仍不能單獨代表業務影響。

錯項一

Facility=6、Severity=16。

錯項二

Severity=6 就代表第六級資安事故。
