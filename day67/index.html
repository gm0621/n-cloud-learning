02

先備能力與三個本課概念

開始前先確認
  • 能計算同一 SNMP Counter 兩次讀值的期間增量，而不把累積值當增量。
  • 能分辨 Flow、Syslog、SNMP、Ping 與 Web 探測各自能直接支持的問題。
  • 能區分觀察、假設、驗證與變更 Gate；缺少受控來源或超出核准範圍時停止。
Syslog 事件

傳達來源產生的離散訊息與嚴重度等欄位；能否證明動作成功取決於原文與來源語意。

別混淆：有事件文字不代表保存了每筆網路通聯或封包內容。

IPFIX／Flow

以流量紀錄描述端點、時間、位元組、封包與協定等中繼資料，適合通聯與用量分析。

別混淆：Flow 通常不含完整應用內容，也不能單獨證明惡意。

SNMP 與主動探測

SNMP 讀取管理物件與 Counter；Ping、Port、Web 等探測由測點驗證特定層次。

別混淆：Ping 成功不能推出 Web 交易成功；累積 Counter 也不是期間增量。

05

跟著做：每一步都有預期與失敗訊號

1

配對 TEL-01 至 TEL-05 的最直接遙測

輸入：讀取題號、要回答的問題與最直接資料三欄。

預期：五題依序配對 Flow、SNMP Counter、Syslog、Web 探測、Ping 探測。

證據：答案表保留 TEL 題號及原始問題文字。

失敗：任一題以較低層旁證取代最直接資料即記為錯配。

2

驗算 TEL-02 的 Counter 證據規則

輸入：以「介面錯誤是否增加」及「兩次讀值的期間增量」為輸入。

預期：寫出後值減前值的算式與同一介面、同一 Counter、兩個時間點條件。

證據：保留前值、後值、時間與差值四欄。

失敗：只有單點累積值或 Counter 重置未處理時，結論不可判定。

3

建立交易與可達性的反證對

輸入：比較 TEL-04 Web 探測與 TEL-05 Ping 探測。

預期：Web 僅代表指定測點交易；Ping 僅代表測點到主機回應，兩者不得互推。

證據：反證表同時引用 TEL-04、TEL-05 與各自限制。

失敗：宣稱 Ping 成功等於登入成功，或單一 Web 測點代表所有使用者即失敗。

4

完成五題證據界線審核

輸入：逐題核對「可證明」與「不能單獨證明」。

預期：五題都有正向能力及一項明確不能證明的結論。

證據：輸出五列完整對照與需補資料欄。

失敗：漏題、越界推論或捏造產品欄位時不交付。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

TEL-01～TEL-05 中，Flow、SNMP Counter、Syslog、Web 探測與 Ping 的配對互換，答案只能說「都有資料」而無法直接回答題目。

最小檢查：逐題先讀「要回答的問題」：通聯端點與量、介面錯誤增量、來源登入失敗事件、登入頁交易、主機可達性，再核對所選資料是否直接產生該證據。

預期：TEL-01=Flow、TEL-02=SNMP Counter、TEL-03=Syslog、TEL-04=Web 探測、TEL-05=Ping 探測，且每列保留題號與原問題。

修正：將較低層旁證移到補充資料欄，按五個問題重新配對最直接來源，並補寫各來源「不能單獨證明」的界線。

停止／升級：若以 Ping 取代 Web 交易、以 Syslog 取代所有網路嘗試，或以 Flow 宣稱內容／惡意，該題不得通過。

TEL-02 把後值當成期間錯誤量，或 Counter 重置後算出負增量仍直接下結論。

最小檢查：確認前值與後值來自同一介面、同一 Counter 且有兩個時間點；先寫「期間增量＝後值－前值」，再檢查重啟、回捲或位元寬度變化跡象。

預期：無重置時以兩點差值回答錯誤是否增加；若讀值回捲或資料不連續，結論標示不可判定並保留原始四欄。

修正：補齊前值、後值、時間與差值，將單點累積值移出增量欄；偵測到重置時切分觀測窗並取得重置後第二個有效樣本再算。

停止／升級：只有一個讀值、介面／Counter 不同或重置狀態未釐清時，不得報告期間增量或根因。

TEL-05 Ping 有回應後，報告將 TEL-04 登入頁直接判為成功；或單一 Web 測點被描述成所有使用者都正常。

最小檢查：並列 TEL-04 與 TEL-05 的測點、目標、層次及結果，確認 Ping 只測主機回應，Web 探測才檢查指定登入交易的狀態與延遲。

預期：兩筆證據可同時成立且不互推：主機可達不等於登入成功；指定 Web 測點成功也不代表所有地點與使用者體驗。

修正：把結論拆成「網路層可達性」與「指定測點交易結果」，為使用者範圍或後端原因另列所需測點、日誌與交易證據。

停止／升級：缺少 Web 交易結果時不得宣稱應用可用；只有單一測點時不得外推到所有使用者。

12

教師版與錯項解析

案例答案

Flow；它回答通聯端點、量與服務，但仍不提供完整內容。

錯項一

SNMP，因為它會保存每筆通聯。

錯項二

Ping，因為成功就能知道傳輸內容。

完成獨立任務後再展開參考成果
  • 通聯端點與流量優先選 Flow，並註明沒有完整內容。
  • 介面錯誤率須由同一 Counter 的時間差計算，不能讀單點累積值。
  • Web 交易應用 Web 探測；Ping 與 Port 只提供較低層旁證。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
