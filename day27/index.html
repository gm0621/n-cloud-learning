02

先備能力與三個本課概念

開始前先確認
  • 能辨識應用紀錄的事件起始列
  • 能保存換行與字元編碼原貌
  • 了解檔案輪替可能切斷事件
事件起始規則

多行 parser 應先定義新事件的可靠起始模式，其餘符合條件者才作續行。

別混淆：每個換行不是新事件，所有換行也不能一律移除。

續行與邊界

堆疊行要附著於正確起始事件，遇下一筆起始列必須立即關閉前一事件。

別混淆：縮排行或單一關鍵字通常不足以涵蓋全部例外。

輪替與編碼

檔案輪替、截斷與無效字元可能破壞邊界，必須作為正式反例測試。

別混淆：單一正常 ASCII 樣本通過不能代表 parser 穩定。

03

位置、版本與安全 Gate

候選入口｜必須以實機版本與角色核對設備管理 → 自定義資料格式；來源輪替設定屬另一 Gate

教材只固定工作目的與驗收證據，不把未核對的子選單、按鈕或欄位畫成真實 UI。

G0／G2

操作邊界

  1. G0 可用去識別樣本反覆練習。
  2. G1 只查詢、檢視與核准匯出。
  3. G2 僅在核准 LAB 建立可清理物件。
  4. 任何外送、正式來源、自動執行、升級或服務變更均須逐項 G3 Gate。

05

跟著做：每一步都有預期與失敗訊號

1

凍結正常與例外原始樣本

輸入：五組保留換行、編碼與檔案邊界的資料

預期：每組原始行數與內容指紋固定

證據：測試集版本與預期事件數清單

失敗：複製時移除換行或自動改變編碼

2

撰寫事件起始與續行規則

輸入：時間戳起始模式、堆疊模式與終止條件

預期：規則可解釋正常列和八行 exception

證據：每種原始列標註 start 或 continue

失敗：僅用是否包含 ERROR 判定新事件

3

執行五案例事件邊界比對

輸入：fixture 的行數、事件數與特殊條件

預期：正常、堆疊、後續、Unicode 結果全符合預期

證據：實際事件數與逐列歸屬差異表

失敗：只計事件數而未確認每列歸屬

4

測試輪替並記錄能力限制

輸入：跨檔堆疊樣本與 parser 輪替行為

預期：成功重建或明確標示不支援與 fallback

證據：輪替前後原文索引及限制說明

失敗：無聲丟列或把兩件事件黏成一件

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

每行堆疊都被切成獨立事件

最小檢查：確認起始模式是否過寬且續行規則是否實際套用

預期：只有帶完整起始時間格式的列開新事件

修正：縮小起始模式後重跑全部五案例

停止／升級：不得只修 exception 而跳過正常案例回歸

下一筆 INFO 黏在 exception 後方

最小檢查：檢查新起始列是否優先於續行規則

預期：新起始一出現即關閉上一事件

修正：調整規則優先序並逐列比較歸屬

停止／升級：仍有歧義時保留原文並標記解析失敗

繁體字元變成替代符號

最小檢查：比對來源宣告、讀取編碼與輸出編碼

預期：Unicode 字元往返後內容指紋一致

修正：統一編碼並重讀未被破壞的原始樣本

停止／升級：原始位元組已遺失時不得聲稱內容完整

來源、版本與複核狀態

  • Unicode Standard Annex 15 Normalization Forms｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-22｜適用：Unicode 正規化與字元保存考量
  • N-Cloud 多行 parser 與輪替之當期受控說明｜CONTROLLED_SOURCE_REQUIRED｜複核：UNKNOWN｜適用：產品多行規則、限制、入口與版本行為

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。

教師版與錯項解析

案例答案

以事件起始模式定義續行規則，並同測 exception、下一筆 INFO、輪替與異常字元。

錯項一

刪除所有換行符號即可。

錯項二

只保留第一行，其他行不重要。

完成獨立任務後再展開參考成果
  • 正常兩列形成兩事件；八行 exception 形成一事件；其後 INFO 必須另開新事件。
  • Unicode 三列需完整保留字元與換行，不可因解碼失敗丟棄。
  • 跨檔輪替若無法可靠重建，必須保留原文並標記限制，不能默默黏合。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
