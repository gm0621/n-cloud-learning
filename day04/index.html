01

Flow 像網路的通聯明細

它通常記錄一段通訊的來源、目的、Port、協定、開始時間、持續時間、封包與 Bytes，但不等於看見傳輸內容。

今天的問題
「下午兩點網路變慢，是哪台主機占用最多頻寬？」

先依來源主機彙總 Bytes 找主要流量，再確認目的、應用、時間與是否符合工作情境。

核心觀念

Flow 擅長回答「誰與誰、何時、用什麼協定、傳了多少」；它通常不能單獨回答「內容是什麼」。

02

五元組定義一段通聯

SRC IP

來源位址

誰發起或送出這段通訊。

DST IP

目的位址

資料要送到哪裡。

SRC PORT

來源 Port

通常是用戶端暫時 Port。

DST PORT

目的 Port

常用來推測服務類型。

PROTOCOL

協定

例如 TCP、UDP 或 ICMP。

模擬 Flow14:01:10 10.0.0.24:53120 → 203.0.113.40:443 TCP bytes=900MB packets=648000 duration=180s

Port 443 常見於 HTTPS，但只靠 Port 仍不能保證應用內容；還需搭配資產、DNS、Proxy 或其他證據。

03

先確認方向，再解讀數字

上傳或送出

來源端送往目的端的 Bytes。大量送出可能是備份、同步、上傳，也可能需要調查。

下載或接收

反向 Flow 或對應欄位呈現回傳流量。必須先理解平台如何定義方向。

1選時間窗對準使用者回報時間
2選維度來源、目的或應用
3選指標Bytes、Packets、Sessions
4查看背景資產用途與基準線

以來源 IP 加總後，10.0.0.24 共 1,550 MB，是這個時間窗的 Top Talker。下一步仍要確認它是不是排程備份或合法同步。
