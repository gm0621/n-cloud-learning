02

先備能力與三個本課概念

開始前先確認
  • 能閱讀 HTTP 請求、狀態碼與最小 JSON 資料契約
  • 能使用 localhost 或隔離測試端點而不外送資料
  • 能辨認憑證材料並使用安全儲存與撤銷流程
Webhook 機制

Webhook 是由事件觸發 HTTP 請求的整合機制；機制本身不是秘密，可以公開描述其資料流與錯誤處理。

別混淆：不可因為機制可描述，就公開實際端點或認證材料。

Webhook 憑證

Webhook URL、存取 token 與 signing secret 都可能授予傳送、辨識或驗證能力，必須視為憑證安全保存。

別混淆：完整 URL 即使沒有明寫密碼，也可能包含不可公開能力。

最小 Payload

最小 payload 只含接收端完成目的所需欄位，以虛構識別與分類取代帳號、原文、token 或其他敏感內容。

別混淆：方便除錯不是傳送完整事件與標頭的充分理由。

有限重試

有限重試為暫時失敗設定明確次數、間隔、總時限與停止條件，並以冪等識別避免重複副作用。

別混淆：收到伺服器錯誤不代表可以無限快速重送。

05

跟著做：每一步都有預期與失敗訊號

1

定義最小通知契約並記錄證據

輸入：只選 event_id、severity 與 occurred_at 三欄

預期：payload 不含帳號、原文、URL、token 或 signing secret

證據：欄位白名單與禁止欄位掃描結果均為零命中

失敗：為方便除錯而附上完整事件、標頭或憑證

2

配置隔離本機端點並記錄證據

輸入：只使用 http://localhost:8080/mock 模擬回應

預期：測試流量不離開本機且不需真實第三方憑證

證據：端點設定、監聽範圍與測試前網路邊界紀錄

失敗：貼入真實 Webhook URL 或改連未核准外部服務

3

驗證一次有限重試並記錄證據

輸入：第一次模擬 500，等待兩秒後第二次回 200

預期：相同 event_id 共兩次請求，成功後不再送第三次

證據：請求序列、回應碼、間隔與總次數可核對

失敗：改變事件識別、立即狂送或成功後仍持續重試

4

掃描並完成撤銷清理且記錄證據

輸入：檢查教材、log、截圖與設定後移除測試材料

預期：Webhook URL、token、signing secret 洩漏數皆為零

證據：掃描結果、撤銷紀錄與端點停止狀態

失敗：任何憑證出現在 Repo、教材、聊天或一般 log

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

獨立任務 · 約 25 分鐘

以 localhost 模擬端點驗證最小 Webhook payload、一次有限重試與憑證零洩漏。

限制

  • Webhook 機制可描述，但 URL、token、signing secret 必須視為憑證
  • 只能使用 localhost 且不得連接真實第三方服務
  • 最多兩次請求，第二次成功後必須立即停止

必交欄位

  • Payload 欄位白名單
  • 禁止敏感欄位清單
  • 本機端點邊界
  • 請求與回應序列
  • 重試與停止條件
  • 憑證掃描及撤銷證據

10

本課專屬排錯

500 後產生大量重試

最小檢查：檢查最大次數、退避間隔、成功停止與排程並行數

預期：同一 event_id 最多兩次且第二次成功後歸零

修正：停用傳送器並在 dry-run 修正上限與停止條件

停止／升級：無法立即停止或可能外送時升級為安全事件

一般 log 出現完整端點

最小檢查：搜尋 URL、token、簽章標頭與設定序列化輸出

預期：所有輸出只保留遮罩識別且零憑證內容

修正：移除紀錄、輪替受影響憑證並修正 log 遮罩

停止／升級：真實憑證可能暴露時立即撤銷並通報

接收端回 400 而不是 200

最小檢查：比對欄位名稱、型別、必填與內容格式契約

預期：能定位單一契約差異且不增加敏感欄位

修正：修正本機 payload 後另開受控測試案例

停止／升級：不得以貼入完整事件或真實憑證方式除錯

案例答案

錯項二

完成獨立任務後再展開參考成果
  • Webhook 機制本身不是秘密，可以描述事件觸發 HTTP 請求的設計。
  • Webhook URL、token 與 signing secret 是憑證材料，不得出現在教材、Repo、截圖、聊天或一般 log。
  • LAB40-001 第一次 500 後僅重試一次，第二次 200 後第三次請求不得發生。
安全界線

只有具逐項核准且使用隔離測試收件匣或端點時，才可執行一次本課 G3 測試；否則只完成 plan／dry-run。禁止正式收件者、正式資料與無上限重試。
