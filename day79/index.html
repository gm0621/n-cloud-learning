05

跟著做：每一步都有預期與失敗訊號

1

建立十二列與 CP0～CP6 的主時間線

輸入：依時間、來源、紀錄ID整理全部十二筆。

預期：十二筆各出現一次，並覆蓋 CP0、CP1、CP2、CP3、CP4、CP5、CP6。

證據：時間線以 REQ-WEB-1、EV／SN／FL／PM／DB／CL ID 索引。

失敗：少於十二筆、ID 重複或缺任一 checkpoint 即失敗。

2

計算 EV-102 顯示時間偏移

輸入：比較 EV-102 事件時間 09:06 與畫面 09:14。

預期：算得 +8 分鐘，保留原文時間並將轉換列為 parser 差異。

證據：偏移算式 09:14−09:06=8 分及修正前後欄位。

失敗：改寫原始事件、算錯符號或只調看板資料即不通過。

3

以多源證據檢驗鏈路不穩假設

輸入：使用 EV-101、SN-201、FL-301、PM-401、PM-402、EV-103、PM-403。

預期：支持 09:04–09:09 鏈路不穩；SN-202 errors增量0 不足以排除 link flap。

證據：假設表分列支持、反對、限制及紀錄ID。

失敗：以單一來源定案、把 loss 35% 當根因或忽略反證即失敗。

4

驗收看板與 CP6 清理

輸入：比較 DB-501 09:12 紅色與 CL-601 09:20 回基準。

預期：DB-501 標更新窗待查、不改事件；CP6 有 LAB 無殘留證據。

證據：CP5 下鑽規格與 CP6 清理計數均可核對。

失敗：把紅色當新事故、缺清理基準或任一 CP 無證據時不交付。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

本課專屬排錯

主時間線不是十二筆、同一紀錄 ID 重複，或 CP0～CP6 中有 checkpoint 沒有證據。

最小檢查：以 ID 清點 REQ-WEB-1、EV-101、SN-201、FL-301、PM-401、PM-402、EV-102、SN-202、EV-103、PM-403、DB-501、CL-601，按絕對時間排序並映射 CP0～CP6。

預期：十二個 ID 各出現一次；09:04 的 EV-101／SN-201 與 09:05 的三筆資料保留同時點，七個 checkpoint 全有對應紀錄。

修正：用紀錄 ID 去重而非刪除同時點事件，補回遺漏來源並保留原始時間與時區；重新產出 ID→時間→checkpoint 索引。

停止／升級：少於十二個唯一 ID、需改寫原始時間才能排序，或任一 CP 仍無證據時，不得進行根因結論或交付。

EV-102 在畫面顯示 09:14，卻被當成 09:14 的新事件，或為對齊圖表而改掉原始 09:06。

最小檢查：同時保留 EV-102 的原文事件時間 09:06 與畫面時間 09:14，計算顯示減事件時間，並比較 parser v2 修正前後欄位。

預期：偏移為 +8 分鐘（09:14−09:06），差異歸在時間轉換／parser 顯示層；原始事件時間保持 09:06。

修正：修正 parser v2 的時間／時區轉換，不修改原文或只調 Dashboard；以固定樣本重跑時間欄位回歸，再將 EV-102 放回 09:04–09:09 主窗分析。

停止／升級：原文時間或時區不可取得、偏移符號無法確認，或修正會覆寫原始資料時，停止時間因果判定並保留 UNKNOWN。

網站慢被單憑 loss 35% 或單一 Syslog 定案，或 09:12 的 DB-501 紅色被誤判成第二起事故。

最小檢查：分列 EV-101、SN-201、FL-301、PM-401、PM-402、EV-103、PM-403 的支持／反對／限制；另核對 SN-202 errors 增量 0、DB-501 更新窗與 CL-601 清理基準。

預期：多源證據共同支持 09:04–09:09 鏈路不穩假設，但不把相關性寫成已證根因；SN-202 不足以排除 flap，DB-501 標為更新窗待查，CP6 證明 LAB 無殘留。

修正：把單源斷言改成有紀錄 ID 的假設表，納入恢復事件 EV-103／PM-403 與限制；對 DB-501 查展示更新窗而不改事件，並補齊 CL-601 的物件及清理計數。

停止／升級：無法保留反證、缺指定多源 ID、把看板狀態當原始事件，或 CP6 未回基準時，不得宣稱根因確定或演練完成。
