02

先備能力與三個本課概念

開始前先確認
  • 能閱讀去識別 Windows 事件
  • 了解代理程式資料路由概念
  • 能分層檢查服務與網路連線
Input Route Output

NXLog 流程由輸入模組取得事件，經 route 選擇後由 output 模組送往接收端。

別混淆：服務正在執行不代表每一段資料路徑都成功。

端到端關聯鍵

測試事件應保留虛構事件 ID、來源時間與內容指紋，以便兩端精確配對。

別混淆：只靠相近時間可能把不同事件錯誤關聯。

中斷點定位

依來源產生、input 讀取、route 處理、output 傳輸與接收逐段找最後成功點。

別混淆：接收端無資料不能反推來源一定沒有事件。

05

跟著做：每一步都有預期與失敗訊號

1

建立單筆去識別測試事件

輸入：虛構事件 ID、固定訊息與來源時間

預期：來源可找到唯一 LAB-EVT-2601 事件

證據：事件 XML 摘要不含帳號或真實主機名稱

失敗：使用正式安全紀錄或無唯一識別的事件

2

畫出 input route output 資料旅程

輸入：來源、NXLog 三階段與虛構接收端

預期：每段均標示輸入輸出與健康檢查

證據：資料流圖具有最後成功點欄位

失敗：只畫來源直達接收端而漏掉 route

3

逐段定位最後成功與首次失敗

輸入：fixture 五階段時間、狀態與證據

預期：最後成功為 route，首次失敗為 output 傳輸

證據：結論引用同一測試事件 ID 與時間

失敗：因接收為零便重裝來源代理程式

4

修正 LAB 條件並重跑同一事件

輸入：核准的測試網路條件與原事件樣板

預期：五階段皆成功且兩端內容指紋一致

證據：修正前後逐段差異與清理紀錄

失敗：同時改事件內容、路由與目的端導致不可歸因

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

來源有事件但 input 計數不增

最小檢查：檢查來源類型、讀取權限、書籤與事件篩選

預期：可確認 input 是否讀到指定測試 ID

修正：在 LAB 修正單一讀取條件後重送事件

停止／升級：需要正式主機權限變更時停止並送審

route 成功但 output 失敗

最小檢查：檢查目的名稱解析、Port、TLS 與重試上限

預期：找到可觀察的第一個傳輸失敗證據

修正：只修正核准測試條件並有限次重試

停止／升級：憑證或正式網路政策未知時不得繞過

接收事件時間與來源不一致

最小檢查：比較事件時間、接收時間、時區與傳輸延遲

預期：兩種時間分欄且偏移可被計算

修正：保留原時間並修正解析或顯示時區

停止／升級：來源時間語意未知時不可覆寫原值
