02

先備能力與三個本課概念

開始前先確認
  • 能由兩分點各 1500 EPS 計得總事件率 3000 EPS，並知道未給事件大小時不能換算 GB。
  • 能把 20 分鐘 WAN 中斷、90 日保存與查詢 P95 連到容量及驗收證據。
  • 能區分觀察、假設、驗證與變更 Gate；缺少受控來源或超出核准範圍時停止。
需求追溯

每個元件、容量與驗收點都必須連回來源量、網路限制、保存或使用者需求。

別混淆：畫出元件但沒有需求 ID 不能證明設計必要。

容量情境

平均、尖峰、中斷緩衝與保存分開計算，並保留壓縮、索引與成長未知項。

別混淆：EPS 不能在不知道平均事件大小時直接換成儲存容量。

授權假設

架構可先列計量候選，但正式單位、去重與方案包含項必須標 UNKNOWN。

別混淆：容量算式正確不代表 License 算式也成立。

05

跟著做：每一步都有預期與失敗訊號

1

建立 REQ-01 至 REQ-05 雙向索引

輸入：逐列擷取需求、設計回應、驗收證據與未知項。

預期：五個需求各有前向設計連結與反向驗收連結。

證據：矩陣以 REQ ID 為 key，不以列序代替。

失敗：任一 REQ 無設計、證據或未知項即不完整。

2

計算事件率並封鎖假容量

輸入：用 REQ-01 的兩分點×1500 EPS。

預期：算得 3000 EPS，並將事件大小缺失標為無法推導 GB。

證據：保留 1500×2=3000 EPS 算式與缺參數清單。

失敗：填入每日 GB、90 日容量或壓縮率而無輸入即失敗。

3

展開 WAN 20 分鐘邊界驗收

輸入：使用 REQ-02 的分點緩衝、中斷重送結果、產品上限 UNKNOWN。

預期：形成中斷前序號、中斷期間接收、恢復重送與遺失數四段驗收。

證據：序號對帳表連回 REQ-02 與 20 分鐘條件。

失敗：只寫「可緩衝」而無重送／遺失證據，或猜產品上限時不通過。

4

串接保存、查詢與授權未知項

輸入：使用 REQ-03 至 REQ-05 的每日量校正、P95、規則版本。

預期：90 日模型保留缺參數；持續查詢有 P95 驗收；授權有官方計量問題。

證據：風險表含壓縮索引、硬體規格、官方計量三項 owner。

失敗：把未知容量或授權規則寫成架構既定值即退件。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

追溯表看似有五列，但從驗收證據無法反查 REQ-01～REQ-05，或某個需求缺少未知項。

最小檢查：以 REQ ID 而非列序逐一查驗：REQ-01 序號對帳、REQ-02 中斷重送、REQ-03 每日量校正、REQ-04 P95、REQ-05 規則版本，並確認每列同時有設計回應與未知項。

預期：五個 REQ ID 均可由需求走到設計及驗收，也可由證據反查原需求；事件大小、產品上限、壓縮索引、硬體規格與官方計量仍明示為未知。

修正：用固定 REQ ID 重建索引，將錯掛的證據移回正確需求；缺資料處填 UNKNOWN 與 owner，不以其他列的假設補值。

停止／升級：任一 REQ 缺設計、驗收或未知項，或必須靠猜測產品／授權規格才能補齊時，將矩陣判為不完整並送受控來源確認。

事件率不是 3000 EPS，或表中出現沒有輸入依據的每日 GB、90 日容量、壓縮率或索引倍率。

最小檢查：只取 REQ-01 的兩個分點，各 1500 events/s，核對算式 1500×2=3000 EPS；再檢查是否提供平均事件大小、每日運行秒數、壓縮與索引參數。

預期：唯一可定量結論是總事件率 3000 EPS；因事件大小等參數缺失，GB／日及 90 日儲存量均標示「無法推導」。

修正：更正分點加總並刪除所有臆測容量值，保留缺參數清單；如需容量模型，只寫含事件大小、時間、壓縮與索引的符號公式，不代入虛構產品數字。

停止／升級：事件大小或官方容量邊界未由核准資料提供前，不得發布 GB 結論、採購量或 License 數量。

WAN 中斷測試只寫「可緩衝」，恢復後卻無法證明 20 分鐘內的事件是否全部重送或遺失多少。

最小檢查：依 REQ-02 分四段比對中斷前最後序號、中斷期間應接收序號、恢復後實際重送序號與遺失／重複數，並確認條件明記 20 分鐘及產品上限 UNKNOWN。

預期：序號對帳能逐筆說明中斷前、緩衝期、恢復重送與最終缺口；重送及遺失證據均連回 REQ-02，不把未知上限當已驗證能力。

修正：以去識別測試序號重做邊界對帳，分列遺失、重複與順序差異；將未驗證的緩衝上限列為風險及 owner，而非修改數字讓結果通過。

停止／升級：無起訖序號、無法算出遺失／重複，或測試需超出核准 LAB／產品限制時，停止宣稱 20 分鐘中斷可承受。
