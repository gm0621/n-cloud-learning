先備能力與三個本課概念

開始前先確認
  • 能計算來源 Bytes／母體 Bytes 百分比，得出 10:00 的 40%。
  • 能依連續三次條件維護正常、等待 1/3、等待 2/3、告警 3/3、恢復的狀態機。
  • 能區分觀察、假設、驗證與變更 Gate；缺少受控來源或超出核准範圍時停止。
分析契約

TopN 的時間、母體、維度與指標必須與監控規則及看板一致。

別混淆：三個畫面各自有數字不代表它們能互相驗證。

狀態機

監控應描述正常、等待、告警、恢復與冷卻，並用時間序列預測轉移。

別混淆：單一閾值沒有持續與恢復規則容易抖動。

通知 Gate

通知是外部副作用，未取得逐項核准時只產生 payload 預覽與模擬收件紀錄。

別混淆：Dashboard 成功不表示可以向正式群組送訊息。

05

跟著做：每一步都有預期與失敗訊號

1

重算五分鐘 TopN 百分比

輸入：逐列使用來源Bytes與母體Bytes，套用來源÷母體×100%。

預期：得到 40%、75%、80%、82%、45% 五個可回查值。

證據：計算表保留時間、分子、分母、百分比。

失敗：分母非同列 100、單位不一致或漏列即失敗。

2

重建三次持續規則狀態

輸入：按 10:00 至 10:04 時序讀取規則狀態。

預期：狀態依序為正常、等待1/3、等待2/3、告警3/3、恢復。

證據：狀態轉移表記前態、輸入、後態與時間。

失敗：10:01 或 10:02 提前告警，或 10:04 未恢復即不通過。

3

規格化 Dashboard 顏色與下鑽

輸入：對照五列預期展示及百分比母體。

預期：10:01–10:02 黃、10:03 紅、10:04 綠，皆可下鑽到同列計算。

證據：看板規格連結時間 key 與來源／母體欄。

失敗：顏色沒有數值與狀態依據或無下鑽條件即失敗。

4

審核告警與恢復 payload 預覽

輸入：使用 10:03 模擬 payload 與 10:04 恢復摘要。

預期：兩份預覽含狀態、時間、百分比、證據連結且收件者為空。

證據：保存預覽雜湊索引及「未外送」紀錄。

失敗：建立真實收件者、外送或缺恢復摘要時立即停止。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

五分鐘 TopN 結果不是 40%、75%、80%、82%、45%，或某列百分比無法回查分子與分母。

最小檢查：按 10:00～10:04 逐列套用來源 Bytes÷同列母體 Bytes×100%，確認分子依序為 40、75、80、82、45，分母每列均為 100 Bytes。

預期：五列結果依序為 40%、75%、80%、82%、45%，每個值都保留時間、來源 Bytes、母體 Bytes 與算式。

修正：將跨時間窗引用的母體改回同列 100 Bytes，統一 Bytes 單位並補齊漏列；不要用 Dashboard 顯示值反填計算表。

停止／升級：任一列分母來源不明、單位不一致或缺原始欄位時，不得用該百分比驅動規則或看板。

10:01 或 10:02 就發出告警，10:03 未達告警 3/3，或 10:04 降到 45% 後仍維持告警。

最小檢查：按時間順序重播五列，逐次記錄前態、當列輸入與後態，核對正常→等待 1/3→等待 2/3→告警 3/3→恢復，且計數只由連續命中累加。

預期：10:01、10:02 只呈等待，10:03 第三次連續命中才告警，10:04 產生恢復並結束該次告警序列。

修正：清除由亂序或跨窗資料帶入的持續計數，以 10:00 正常態重新依序重播；分離「命中閾值」與「達三次才告警」兩個判定，補上恢復轉移。

停止／升級：時間序列不完整、連續性無法證明，或重播仍提前告警／缺恢復時，不得啟用規則。

Dashboard 顏色與狀態不一致、無法下鑽到同列算式，或模擬通知出現真實收件者／外送紀錄。

最小檢查：核對 10:01–10:02 黃、10:03 紅、10:04 綠與各時間 key；檢查告警及恢復 payload 是否含狀態、時間、百分比、證據連結，且收件者為空並留有「未外送」紀錄。

預期：黃黃紅綠均可下鑽至同窗來源／母體欄；10:03 告警與 10:04 恢復各有模擬預覽及雜湊索引，全程沒有外部副作用。

修正：以時間 key 綁定看板狀態與計算列，補齊恢復摘要；移除所有收件設定，將連接器改為隔離 mock／預覽模式後再驗證未外送。

停止／升級：發現真實收件者、任何外送嘗試、顏色無數值依據或缺恢復摘要時，立即停用通知路徑並保留稽核證據。
