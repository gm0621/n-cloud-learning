02

先備能力與三個本課概念

開始前先確認
  • 能辨認分隔符與引用字元
  • 能為固定欄位位置編號
  • 了解格式版本需要獨立測試
位置式 schema

Delimiter 格式以欄位位置承載語意，因此每個版本都要固定欄數與位置字典。

別混淆：同名檔案不代表欄位順序永遠相同。

引用與跳脫

值若包含分隔符，必須依格式的引用與雙引號跳脫規則解析完整欄位。

別混淆：直接以逗號 split 會破壞含逗號的訊息。

版本漂移

新增、移除或交換欄位時應辨識版本並 fail safely，避免無聲錯配語意。

別混淆：欄位數相同也可能發生位置語意互換。

03

位置、版本與安全 Gate

候選入口｜必須以實機版本與角色核對設備管理 → 自定義資料格式

教材只固定工作目的與驗收證據，不把未核對的子選單、按鈕或欄位畫成真實 UI。

G0／G2

操作邊界

  1. G0 可用去識別樣本反覆練習。
  2. G1 只查詢、檢視與核准匯出。
  3. G2 僅在核准 LAB 建立可清理物件。
  4. 任何外送、正式來源、自動執行、升級或服務變更均須逐項 G3 Gate。

05

跟著做：每一步都有預期與失敗訊號

1

確認 delimiter 引用與換行規則

輸入：五案例原文、逗號分隔與雙引號引用

預期：可正確數出邏輯欄位而非字面逗號數

證據：逐案例 token 與引用狀態表

失敗：使用單純 split 造成 message 被拆開

2

為每個版本建立位置字典

輸入：v1 五欄與 v2 六欄的欄位名稱順序

預期：兩版各自有編號、型別與必填規則

證據：schema 版本、發布日期與測試 ID

失敗：沿用 v1 第五欄位置解析 v2 message

3

測試缺欄空欄與多分隔符

輸入：尾端空欄、引用逗號及未知 v3 樣本

預期：空值保留、引用正確、未知版本被拒絕

證據：實際欄數與預期處理逐列一致

失敗：自動補欄後無聲套入錯誤位置

4

執行版本回歸與安全 fallback

輸入：v1、v2 全案例和未知版本原文

預期：已知版本通過且未知版本不產生錯配欄位

證據：回歸結果與原文保存位置紀錄

失敗：修正 v2 後使 v1 的 message 消失

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

message 被逗號拆成多欄

最小檢查：檢查引用字元是否完整及讀取器 dialect

預期：引用內逗號保留在單一 message 欄

修正：套用正確引用規則後重跑全部版本

停止／升級：引用未閉合時保留原文並拒絕解析

尾端空欄被讀取器省略

最小檢查：比較原始分隔符數與邏輯欄位數

預期：最後空值仍占據 schema 指定位置

修正：啟用保留尾端空欄並新增回歸案例

停止／升級：欄位位置無法確定時不得向左位移

新版本欄數碰巧與舊版相同

最小檢查：核對版本標記、欄位型別與內容驗證器

預期：語意互換可被型別或版本驗證阻擋

修正：增加版本辨識與欄位級 invariant

停止／升級：無可靠版本訊號時標記 UNKNOWN

12

教師版與錯項解析

案例答案

版本化 schema、支援引用規則並對欄位數與未知版本 fail safely。

錯項一

固定取第 5 欄當 message，版本不用記。

錯項二

直接用逗號切割，忽略引號。

完成獨立任務後再展開參考成果
  • v1 的 message 位於第五欄；v2 新增 region 後 message 移至第六欄。
  • 尾端空欄仍計入欄數，引用內逗號不新增邏輯欄位。
  • v3 無已核准 schema，應拒絕正規化、保留原文並標 UNKNOWN。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
