02

先備能力與三個本課概念

開始前先確認
  • 能區分事件、Flow、SNMP與PM的證明範圍
  • 能保留缺失資料與替代假設
  • 可在限時內建立可追溯證據鏈
多源互證

不同來源在同窗支持同一假設，但不會自動建立因果。

別混淆：來源越多就等於根因已證實。

Flow界線

一般Flow/IPFIX可支持端點、方向、封包／位元組、時間與匯出欄位；不能由通用Flow紀錄宣稱TCP重傳。若產品有衍生重傳欄，必須標產品衍生並附受控來源。

別混淆：把bytes、packets或旗標直接說成重傳證明。

缺口

NO_SAMPLE是證據狀態，不可插值成正常或異常。

別混淆：為了時間線完整而補故事。

03

位置、版本與安全 Gate

候選入口｜必須以實機版本與角色核對事件、Flow、SNMP、PM 與調查工作紙

教材只固定工作目的與驗收證據，不把未核對的子選單、按鈕或欄位畫成真實 UI。

G0／G1

操作邊界

  1. G0 可用去識別樣本反覆練習。
  2. G1 只查詢、檢視與核准匯出。
  3. G2 僅在核准 LAB 建立可清理物件。
  4. 任何外送、正式來源、自動執行、升級或服務變更均須逐項 G3 Gate。

05

跟著做：每一步都有預期與失敗訊號

1

建時間線：依「跨資料事件 Capstone教學資料集（去識別）」逐列處理

輸入：12列相對時間與來源

預期：12/12保留觀察及限制

證據：正證：event flap與PM timeout同窗；負證：無核准變更；失敗：SNMP缺口

失敗：把SNMP缺口寫成0即失敗

2

建立假設：依「跨資料事件 Capstone教學資料集（去識別）」逐列處理

輸入：鏈路不穩、應用故障、測點問題

預期：主假設與至少兩個替代假設

證據：每個假設都有支持與反證

失敗：只有單一根因敘事不得滿分

3

審核Flow用語：依「跨資料事件 Capstone教學資料集（去識別）」逐列處理

輸入：4筆flow列；使用「跨資料事件 Capstone教學資料集（去識別）」對應欄位

預期：只寫端點、443、bytes／packets趨勢；重傳=UNKNOWN

證據：證據明載「不證明重傳」

失敗：若使用產品衍生欄，未附來源即刪除該主張

4

交付與質詢：依「跨資料事件 Capstone教學資料集（去識別）」逐列處理

輸入：證據鏈、限制、下一步

預期：同儕可用ID逐項挑戰；無G3動作

證據：留下接受／拒絕反證紀錄

失敗：編造缺失資料或未核准操作即不通過

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

Flow欄位寫retransmission

最小檢查：查欄位是原始IPFIX還是產品衍生

預期：有明確名稱、算法、版本、受控來源

修正：無來源就改為UNKNOWN並用封包擷取等適當資料驗證

停止／升級：未取得來源不得用於結論

SNMP中斷

最小檢查：查collector健康與最後樣本

預期：缺口起訖可界定

修正：標NO_SAMPLE並以其他來源旁證

停止／升級：不得插值成0

來源時間對不上

最小檢查：查事件時間、接收時間與偏移

預期：偏移可量化

修正：統一UTC並保留原值

停止／升級：偏移未知時不宣告先後因果

來源、版本與複核狀態

  • RFC 7011: IPFIX Protocol｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-21｜適用：Flow匯出資料與資訊元素框架；不把通用Flow誤稱TCP重傳證據
  • RFC 9293: Transmission Control Protocol｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-21｜適用：TCP行為與重傳屬TCP端點／封包語意，非任意Flow計數即可證明

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。

教師版與錯項解析

案例答案

提出鏈路不穩的主要假設與多源支持，同時標示一般 Flow 不能證明 TCP 重傳、SNMP 有缺口，並列替代假設。

錯項一

四類資料不全，所以不能做任何判讀。

錯項二

Web timeout 已單獨證明資料庫故障。

完成獨立任務後再展開參考成果
  • 主假設：鏈路flap可能造成同窗交易中斷；支持為event down/up、PM timeout及Flow量變化。
  • 替代假設：應用短暫故障或單一PM測點問題；需其他測點／應用log檢驗。
  • Flow只顯示通聯與量的變化，未提供可據以證明重傳的已驗證欄位；重傳保持UNKNOWN。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
