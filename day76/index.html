先備能力與三個本課概念

開始前先確認
  • 能依 v1 五欄與 v2 六欄的 schema 逐欄比較，而非依固定位置猜未知版本。
  • 能辨認 Unicode 替代符號、明示空值、多餘分隔符與多行事件切割等 Parser 失敗。
  • 能區分觀察、假設、驗證與變更 Gate；缺少受控來源或超出核准範圍時停止。
事件邊界

先定義每筆事件的開始與續行規則，才能處理堆疊、多行與輪替。

別混淆：每一行不一定是一件事件，合併所有行也不正確。

Fail safely

未知版本或欄位數不符時保留原文並標解析失敗，避免靜默錯配到錯欄。

別混淆：保留原文不代表可以忽略告警與修正。

回歸集合

正常、缺值、Unicode、異常分隔與舊版樣本都要有欄位級預期。

別混淆：新樣本通過不代表舊格式沒有被破壞。

05

跟著做：每一步都有預期與失敗訊號

1

建立 v1／v2 版本化欄位字典

輸入：使用 P-01 五欄與 P-04 新增 region 的六欄預期。

預期：產生互不覆寫的 v1 五欄、v2 六欄定義。

證據：字典標示版本、欄數、欄名及原始雜湊索引。

失敗：沿用 v1 位置解析 v2 或未記版本即失敗。

2

檢查 Unicode 與缺值保真

輸入：比對 P-02 顯示名稱、P-03 result 缺值及原文。

預期：P-02 原字元完整；P-03 保留整筆與原文並呈現明示空值。

證據：逐欄差異表引用 P-02、P-03。

失敗：出現替代符號或因缺值丟棄整筆即不通過。

3

隔離未知版本並合成多行事件

輸入：使用 P-05 多一分隔符與 P-06 多行 stack。

預期：P-05 明確失敗且隔離；P-06 仍為一事件。

證據：錯誤佇列記 P-05 原因，事件計數記 P-06=1。

失敗：P-05 靜默成功或 P-06 被切成多筆即失敗。

4

重跑 P-01 至 P-06 全組回歸

輸入：以修正版本、六筆固定輸入及逐欄預期進行比較。

預期：六筆全部符合；任一舊版欄位消失則整組不通過。

證據：回歸表逐筆列 expected／actual／差異／回復版。

失敗：少跑一筆、只測修正樣本或缺回復版即停止交付。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

P-04 的 region 被解析到舊欄位，或 v1／v2 共用同一位置定義而造成欄位錯位。

最小檢查：比較 P-01 的 v1 五欄與 P-04 的 v2 六欄，逐一核對版本、欄數、欄名及原始樣本雜湊索引，不用固定位置猜測版本。

預期：v1 保持五欄，v2 有獨立六欄 schema 並包含 region；兩版定義互不覆寫，輸出可追溯到原始雜湊。

修正：先以明確版本分流，再套用各自欄位字典；未知或欄數不符者走失敗隔離，不回退套用 v1。修正後重跑 P-01～P-06。

停止／升級：版本無法辨識、雜湊索引遺失，或修正 v2 導致 P-01 任一舊欄位消失時，整組不得交付。

P-02 顯示名稱出現 Unicode 替代符號，或 P-03 因 result 缺值而整筆消失。

最小檢查：把 P-02、P-03 原文與逐欄 actual 並排，比對解碼前後位元／字元結果、result 的明示空值及原始雜湊是否仍存在。

預期：P-02 原 Unicode 字元完整保留；P-03 仍是一筆事件，result 明示為空且原文可回查。

修正：在正確輸入邊界統一字元解碼，禁止以替代符號靜默取代；將缺值分支改成保留事件與原文、只把 result 設為明示空值，然後執行六筆全回歸。

停止／升級：無法確認原始編碼、原文已遺失，或任何修正會丟棄事件／改寫原始樣本時，停止發布 parser。

P-05 多一個分隔符卻被靜默解析成功，或 P-06 的多行 stack 被拆成多筆事件。

最小檢查：查看 P-05 是否以未知版本與欄數不符進入錯誤佇列並記原因；查看事件邊界規則及 P-06 的事件計數是否為 1。

預期：P-05 保留原文、明確標示解析失敗並隔離；P-06 的首行與續行合成單一事件，計數等於 1。

修正：將欄數／版本驗證前置，失配時 fail safely；依明確首行與續行規則修正多行切割。保留回復版並重跑 P-01～P-06 的 expected／actual 差異。

停止／升級：P-05 仍靜默成功、P-06 仍非 1 筆、少跑任一固定樣本，或沒有可回復版本時，停止交付。

來源、版本與複核狀態

  • RFC 5424：The Syslog Protocol｜VERIFIED_OFFICIAL_PUBLIC｜複核：2026-10-22｜適用：標準 Syslog 訊息結構與傳輸考量；本課虛構格式及 N-Cloud parser 實作不由 RFC 保證。
  • N-Partner／N-Cloud 當期受控文件｜CONTROLLED_SOURCE_REQUIRED｜複核：UNKNOWN｜適用：N-Cloud 自定義資料格式、parser 語法、部署與 rollback 方法待版本受控文件確認。

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。
