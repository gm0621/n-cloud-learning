02

先備能力與三個本課概念

開始前先確認
  • 能分辨 CEF header 與 extension
  • 能解析 extension 的 key-value
  • 了解自訂槽位需由 Label 命名
CEF Header

CEF 前綴後的七個管線分隔欄位描述版本、供應者、產品、版本、簽章、名稱與嚴重度。

別混淆：header 的 Severity 與 extension 自訂值不是同一欄位。

Extension 配對

extension 以 key=value 承載資料，自訂槽位 cs1 應與 cs1Label 成對決定語意。

別混淆：cs1 只是槽位名稱，不能永久假設代表部門。

缺 Label 策略

自訂值缺少對應 Label 時應保留槽位與原值並標 UNKNOWN，不自行補語意。

別混淆：值看似 high 也不能猜成風險、優先級或敏感度。

05

跟著做：每一步都有預期與失敗訊號

1

先拆解 CEF header 七欄

輸入：去識別 CEF 前綴與七個管線分隔欄位

預期：七欄數量、順序與跳脫處理均正確

證據：header 逐欄索引及原文位置

失敗：把 extension 的管線或跳脫字元錯當分隔

2

解析 extension 的鍵值邊界

輸入：五案例的空白、等號跳脫與重複槽位

預期：每個 key 與完整 value 邊界可追溯

證據：token 清單與跳脫還原前後值

失敗：把 a\=b 錯切成額外 key

3

配對自訂 value 與 Label

輸入：cs1 至 cs5 及相同編號的 Label 欄

預期：只有完整配對才產生具名業務欄位

證據：配對矩陣列出完整、缺值與缺 Label

失敗：把所有 cs1 都硬編碼為 Department

4

執行缺漏重複與回歸測試

輸入：完整、缺 Label、無值、跳脫與重複五案

預期：五案狀態符合 fixture 且原文皆保留

證據：逐案 expected actual 差異為零

失敗：缺 Label 時猜測語意或無聲覆寫重複值

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

CEF header 欄位數超過七個

最小檢查：檢查管線字元是否在欄值中正確跳脫

預期：只有未跳脫管線作為 header 分隔符

修正：修正跳脫辨識後重新拆解完整訊息

停止／升級：原文已失去跳脫資訊時停止欄位映射

cs 值存在但具名欄位為空

最小檢查：確認同編號 Label 是否存在且非空值

預期：完整 value Label 對才建立具名欄位

修正：缺 Label 時保留原槽位並標 UNKNOWN

停止／升級：不得依過去樣本自行沿用 Label

重複自訂槽位被無聲覆寫

最小檢查：檢查 parser 的重複 key 優先政策

預期：兩值皆保留或明確拒絕並產生警告

修正：設定可測的多值政策並回歸全部案例

停止／升級：政策未核准前不得選一值做業務決策

  • N-Cloud CEF parser 當期受控說明｜CONTROLLED_SOURCE_REQUIRED｜複核：UNKNOWN｜適用：產品映射、重複欄位、fallback 與版本行為

來源 Gate：標示 CONTROLLED_SOURCE_REQUIRED 的產品能力、路徑、授權或政策，在取得當期受控來源前一律是 UNKNOWN，不作為正式操作或報價依據。

教師版與錯項解析

案例答案

cs1 可標為 Department=finance；cs2 保留原槽位並標 UNKNOWN，不猜 high 的語意。

錯項一

cs1 永遠代表 Department。

錯項二

cs2=high 一定代表風險等級。

完成獨立任務後再展開參考成果
  • cs1 與 cs1Label 完整配對，因此可正規化為 Department=finance。
  • cs2 缺 cs2Label，只能保留 cs2=high 並標 UNKNOWN，不能稱為風險等級。
  • 跳脫值還原為 a=b；重複 cs5 依明文政策保留兩值並提出警告。
安全界線

先用 G0／G1 建立證據，再依核准進 G2；任何外送、正式來源、自動執行、升級、重啟或回復都停在 G3 Gate 前。
