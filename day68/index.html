05

跟著做：每一步都有預期與失敗訊號

1

定義 09:00–09:15 的 TopN 母體

輸入：使用「找前五來源」列的時間窗與 Bytes 固定條件。

預期：產生可重現的同窗母體規格，再定義 Bytes 降冪取五名。

證據：記錄起訖時間、時區、量值欄、排序方向與 N=5。

失敗：窗、時區或量值欄缺一時不得產生排行。

2

拆分趨勢與排行的聚合契約

輸入：對照「看事件趨勢」的事件數與 TopN 的 Bytes。

預期：兩者共享時間窗但保持不同量值與聚合，不把事件數排行解讀成 Bytes 排行。

證據：需求到功能映射引用兩列及各自單位。

失敗：混合 Bytes 與事件數或未標單位即失敗。

3

規格化交班看板的回查鏈

輸入：讀取時區、更新時間、下鑽入口與元件種類待確認項。

預期：看板規格含顯示時區、最後更新、單位與回到母體查詢的入口。

證據：保存 Dashboard 四項欄位及元件種類 UNKNOWN。

失敗：只有圖表外觀、沒有更新時間或下鑽條件時不通過。

4

界定操作稽核的可證明範圍

輸入：使用物件／角色／時間與去識別歷程。

預期：只陳述歷程記載的角色在何時對何物件做何動作；保存期與權限待查。

證據：稽核索引含物件、角色、絕對時間及來源。

失敗：以目前狀態推回歷史或猜測產品保存期時停止。

停止條件：環境、角色、版本、影響範圍、回復方式或核准任一項不清楚，就停在觀察與設計。

10

本課專屬排錯

「前五來源」在不同人重跑時名次不同，或結果混入 09:00–09:15 以外的資料。

最小檢查：核對起點 09:00、終點 09:15、時區、來源維度、量值 Bytes、降冪排序及 N=5；確認所有人使用同一絕對時間母體。

預期：查詢契約完整記載時間窗與時區，先得到同一母體，再按 Bytes 降冪穩定產生五筆來源排名。

修正：清除相對時間或本機預設時區，明寫絕對起訖與時區；將量值固定為 Bytes、排序固定為降冪、筆數固定為 5 後重跑並保存查詢條件。

停止／升級：時間窗、時區或 Bytes 欄任一未定義時，不得發布 TopN；產品實際欄位名稱未有受控來源時標 UNKNOWN。

事件趨勢與 TopN 顯示的數值被拿來互相比名次，報告未註明一邊是事件數、另一邊是 Bytes。

最小檢查：對照「看事件趨勢」與「找前五來源」兩列，確認雖共享 09:00–09:15 母體，但聚合量值、單位與維度是否分開記錄。

預期：趨勢以同窗事件數呈現時間變化；TopN 以來源維度彙總 Bytes 並排序，兩種結果不互相替代。

修正：拆成兩份聚合契約與圖表，分別標示事件數和 Bytes；任何比較都先回到相同母體及一致單位，不用事件數排名解讀 Bytes 排名。

停止／升級：單位缺失、兩種量值混在同一序列或母體時間不一致時，停止解讀與告警判定。

交班 Dashboard 只有圖表外觀，值班者看不到資料最後更新時間，也無法由異常點回到原始查詢。

最小檢查：檢查看板是否同時顯示時區、最後更新時間、每個量值單位及帶入原時間／篩選條件的下鑽入口；元件種類是否被誤寫為已確認。

預期：每個看板項目都能辨識資料新鮮度與單位，並回查到產生該值的母體；未核實的元件種類維持 UNKNOWN。

修正：補上顯示時區、更新戳、單位與查詢連結規格，讓下鑽保留時間窗及篩選；把未有當期文件支持的 UI／元件名稱改回 UNKNOWN。

停止／升級：無更新時間或無可重現下鑽條件時不得作為交班證據；不得依畫面相似度猜測產品能力。
